## 问题与证据

用户反馈：启用 DLSSNR 后，截图会导致后续画面持续闪烁。用户确认四条抗闪烁路线的对照只切换抗闪烁选项，光流估计、Multi Pass 和其他参数保持相同；静态累积没有观察到异常，光流累积、光流累积+、低频时域重建会出现异常。

分析日志：`C:/Users/81443/Downloads/magpie.1 (15).log`、`C:/Users/81443/Downloads/magpie (36).log`。日志中可见的运行组合为双 Pass、AMD 质量光流、低频时域重建；这些日志不包含静态累积的同条件对照。

两份日志共有 629 次 WGC 拒帧，记录的当前时间戳全部与上一帧相等，没有时间倒退。前两次截图后约 0.2 秒开始密集出现捕获中断、恢复和历史重置。可见的 DLSSNR 推理状态均成功，没有光流提供器失败日志；这不等于光流数值已经验证正确。

## 已定位的代码链路与结论边界

1. `GraphicsCaptureFrameSource::_Update` 原先将 `timestamp <= previousTimestamp` 统一视为捕获中断，导致重复帧也增加捕获序号。
2. `Renderer::_BackendRender` 发现捕获序号变化后调用 `FrameGuidanceService::ResetHistory`，重置光流等历史。
3. `AmdOpticalFlowProvider` 在重置帧清零运动向量和置信度，输出 `isZero=true`；后续正常帧恢复光流。
4. `DLSSNRTemporal::Draw` 的后三条路线据此从使用光流切为不使用光流，恢复时又因 `motion != lastMotion` 再次重置累积。静态累积不发生这种光流模式切换，但仍接收公共历史重置信号。

确定存在的错误是“重复时间戳触发历史重置”。光流模式切换提供了后三条路线更敏感的代码解释，但尚不能完整证明静态累积完全不闪的原因，也不能据此认定截图损坏了光流纹理或估算算法。

普通截图读取前端已提交的效果帧，没有直接调用光流估算或写入光流纹理。截图读回与成功提示中，究竟哪个环节使重复时间戳增多，尚未确认。优先验证上述针对性修复，不先改造整个截图架构，也不直接删除光流模式切换时的历史保护。
