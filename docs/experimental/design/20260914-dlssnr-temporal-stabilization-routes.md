# DLSSNR Multi Pass：减少残差闪烁的技术路线

日期：2026-09-14。研究源码核对基线：`068` 分支，`b9cbdb47`。本文主体保留方案分析；A、B 首版实现见第 13 节，后续 F、G 实现见第 14 节。历史研究建议不表示所有候选均已实现；游戏画质收益尚未实测。

同日补充：已对照“分析 Frostpunk 2 降噪器”会话的 AMD 源码审计与受限输入方案 review。主体与 B/E 重复，有价值的新增机制已并入 B.1～B.3、第 7 节及实验要求；第 12 节记录逐项取舍，保留原有八条路线。

目标：减少 DLSSNR，特别是后续 Multi Pass 产生的局部明暗、色彩和结构修正闪烁；保留可接受的修正强度、运动响应和细节；必要时把低分辨率残差重建回效果器原输入分辨率。这里的“原分辨率”指效果器输入尺寸，不一定等于物理显示器尺寸。

当前界面名称：`无 / 静态累积 / 光流累积 / 光流累积+ / 低频时域重建`。界面已移除路线代号；本文保留 A/B/F/G 作为研究索引，对应如下。此次仅调整显示名称，算法及已有配置数值含义不变。

| --- | --- | --- |
| A | 静态累积 | 1 |
| B | 光流累积 | 2 |

## 1. 推荐方向

最值得先验证的主体是：**对后续 pass 的新增残差做运动补偿和自适应历史累积，用原始输入的一致性决定是否保留历史。** 无光流时保留一个仅在稳定区域累积的版本；如果仍有明显的效果开关闪烁，再加入快慢两套历史或修正区域的持续性判断。

时域累积、光流、历史验证、稳健统计和升采样负责不同问题，可以组合。TAAU 是其中一种重建结构，不是减少闪烁的必要前提，也不应因为需要回到原分辨率就直接移植一整套超分辨率算法。

建议顺序：

1. 取得原图、Pass 1、最终输出和各阶段残差，确认闪烁主要来自哪里。
2. 用保留现有串联行为的原分辨率残差原型，比较无光流和共享光流的自适应累积；总残差与后续新增残差均作为实验模式。
3. 根据剩余问题，选择快慢历史、短窗稳健统计或分频处理中的一项增强。
4. 在效果成立后评估低分辨率历史及联合升采样，优化时间和显存。
5. 改变降采样相位、把稳定结果反馈给后续 NR，保留为独立研究路线。

第二步使用原分辨率，是因为当前 Multi Pass 已经存在完整分辨率的层间结果，差分定义最清楚。它是验证原型的选择，不是预先确定正式版本一定使用原分辨率历史。

## 2. 当前实现与研究边界

此前讨论时源码还是单层后端；本次核对时已经新增 1～3 层 Multi Pass。设计必须依据当前实现。

| 当前事实 | 对时域路线的影响 | 代码或说明 |
| --- | --- | --- |
| 每层使用独立 `DLSSNRFilter`，拥有各自 NGX 特征、队列、资源和历史 | 模型内历史已经按层隔离；外部稳定器是新增的一套历史 | [Multi Pass 后端](../../../src/Magpie.Core/DLSSNRMultiPass.h) |
| 层间纹理使用完整效果器输出尺寸，每层处理上一层的完整输出 | 当前不是“仅降采样一次，所有 NR 在低分辨率连续运行” | [Multi Pass 行为说明](../effects/DLSSNR-MULTIPASS.md) |
| 开启 SDR 输入分辨率调整时，每层先 Lanczos-2 抗混叠降采样，再 NR，再控制残差，最后 Catmull-Rom 升采样并回叠 | 每层的降采样、颜色控制和裁切都会参与下一层输入；重构时不能宣称天然等价 | [DLSSNRFilter.cpp](../../../src/Magpie.Core/DLSSNRFilter.cpp) 中 `PrepareInput`、`PrepareResidual`、`CompositeResidual` |

| 光流来源是共享捕获帧，方向为当前到上一帧，单位为源像素；没有真实引擎深度 | 可以用颜色帧验证重投影，但不能把零深度当作遮挡证据 | [FrameGuidanceTypes.h](../../../src/Magpie.Core/FrameGuidanceTypes.h) |
| AMDOF 普通有效帧的 `DenseConfidence` 固定为 `0.65` | 该数值不能当作逐像素匹配质量，外部滤波器需要自己的历史有效性判定 | [AmdOpticalFlowProvider.cpp](../../../src/Magpie.Core/AmdOpticalFlowProvider.cpp) 中 `Densify` |
| AMDOF Performance 已在宽高各半的输入上估计光流 | 不能再次把“改为半分辨率”计入尚未实现的优化收益；有效块粒度已变粗 | 同文件 `opticalFlowExtent` |
| AMDOF 在 `BeginFrame` 内向 D3D11 上下文插入完成等待，后续 NR 在其后准备输入 | 独立 D3D12 队列不代表与 NR 已经有效重叠 | 同文件 `BeginFrame`；[Renderer.cpp](../../../src/Magpie.Core/Renderer.cpp) |
| 重复捕获帧会复用结果；上游参数变化用输入修订号触发重算 | 时域历史必须按真实新帧更新，参数重算不能当作额外时间样本 | `DLSSNRFilter::Draw`、`DLSSNRMultiPass::ApplyLiveParameters` |
| 当前 FP16 HDR 路径不启用内部降分辨率残差重建 | 建议先验证 SDR；HDR 的残差空间、阈值和输出限制另行设计 | `DLSSNRFilter::Initialize` |

公开 DLSS 5 资料将其描述为带时序状态、确定性的单步扩散推理。因此，“单步扩散”不能直接推出“每次调用都有独立随机噪声”，多次 NR 调用也不等于沿扩散时间步继续求解。当前实际 DLL、输入、历史和引导条件仍需实验确认。[NVIDIA DLSS 5 技术说明](https://research.nvidia.com/labs/adlr/DLSS5/)

## 3. 先区分闪烁类型

| 观察到的现象 | 可能原因，尚需验证 | 更适合的处理 |
| --- | --- | --- |
| 原图稳定，NR 修正小幅快速抖动 | 输入敏感性或时序状态引起的修正波动 | 自适应 EMA；必要时短窗稳健统计 |
| 原图稳定，某片修正反复出现、消失或换位置 | 修正区域在时间上不稳定 | 较长累积、快慢历史、区域持续性判断 |
| 移动后残差边界闪烁或拉丝 | 光流错误、遮挡、插值误差、不同运动混合 | 重投影验证、保守拒绝、局部空间滤波 |
| 调整 Shadow / Glow 后，近零亮度变化突然变强 | 正负方向硬分类叠加不同倍率 | 稳定分类或平滑过渡；对照默认倍率定位 |
| 低分辨率小颗粒放大后明显跳动 | 低分辨率残差变化被锐利插值放大 | 稳健处理、分频、较低振铃升采样 |
| 相机移动、光照或反射确实改变时画面跳动 | 真实内容变化，不一定是算法错误 | 提高响应，避免长历史吞掉真实变化 |
| 停顿、换场景、重开后整幅异常 | 旧历史、错误尺寸或帧身份继续参与 | 修复历史生命周期，不依赖模糊掩盖 |

用 `R_t = S_t + N_t` 表示“稳定修正＋波动”只是一种局部模型。若修正在两个不同外观之间切换，或者模型产生了持续的错误修正，时间平均只能降低变化速度，不能保证得到正确外观。A、B 两片交替修改，可能最终变为两片都存在较弱修正。

## 4. 选择累积什么

设 `X0,t` 为当前效果器原始输入，`Xk,t = Fk(Xk-1,t)` 为第 k 层完整输出。`Fk` 包含该层 NR、缩放、残差参数和最终裁切。以下差分均在同尺寸、同颜色编码的浮点空间计算，历史不使用 UNORM 保存有符号残差。公式省略最终输出范围处理与 Alpha，实际按第 7.5 节处理。

### 4.1 整个 Multi Pass 的总残差

```text
Rtotal,t = XM,t - X0,t
Ot = X0,t + Stable(Rtotal,t)
```

优点是覆盖所有层的波动，不需要假设 Pass 1 稳定。缺点是首层本来迅速出现的正确修正也会受历史影响。如果首层明显闪烁，这应成为主要候选。

### 4.2 后续 pass 的新增残差：推荐的初始实验对象

```text
Rextra,t = XM,t - X1,t
Ot = X1,t + Stable(Rextra,t)
```

只对 Pass 2、Pass 3 相对第一层新增的效果做稳定。当前后端已有 `X1` 中间纹理和最终 `XM`，容易得到精确差分。关闭稳定器时直接返回 `XM`；`M = 1` 时跳过该模式。

这能保留首层响应，但“Pass 1 更稳定”必须由素材验证。还要观察首层与额外修正之间是否存在抵消关系：如果某些闪烁原本由后层即时补偿，单独延缓额外修正可能破坏抵消。

### 4.3 各层增量分别累积

```text
Rk,t = Xk,t - Xk-1,t
Ot = X0,t + Stable1(R1,t) + Stable2(R2,t) + Stable3(R3,t)
```

各层的滤波强度、频率和响应速度可以不同。只有测出各层行为明显不同时才值得增加这组历史；否则合并额外残差更简单。层间存在相关性，不能默认第三层总应使用更长历史。

这里所有 `Xk` 都来自未经外部稳定器反馈的现有串联链。把稳定后的 `X1` 作为 Pass 2 的新输入，会改变模型输入和内部历史，是第 6 节讨论的另一项实验。

## 5. 可组合的技术路线

表中成本为相对成本，不包含额外光流的固定开销；没有给出尚未测量的毫秒承诺。

| 编号 | 路线 | 最适合的闪烁 | 主要限制 | 优先级 |
| --- | --- | --- | --- | --- |
| A | 稳定区域检测＋无光流自适应 EMA | 静止区域的幅度抖动、效果开关 | 运动时覆盖率低，相似颜色也可能掩盖运动 | 第一阶段基线／低成本候选 |
| B | 光流重投影＋输入验证＋自适应 EMA | 运动物体表面及相机移动中的修正抖动 | 错误光流会搬错暗斑和亮斑 | 主体路线 |
| C | 快慢两套历史＋变化确认 | 修正区域持续几帧后又切换，稳定与响应难兼顾 | 切换规则过强会恢复闪烁，过弱会粘住旧效果 | B 的优先增强 |
| D | 短窗中值／稳健加权累积 | 孤立亮暗脉冲、偶发异常残差 | 会误删短暂真实修正；多帧对齐和存储更复杂 | 有脉冲证据时使用 |
| E | 分频或方差引导的时空滤波 | 颗粒闪烁、边缘爬动、低频明暗呼吸并存 | 空间滤波过强会抹掉 NR 细节 | 有频率分布证据时使用 |
| F | 修正区域持续性与迟滞 | 某片修正在“有／无”之间反复跳变 | 阈值可能改变效果覆盖和强度 | 可选增强 |
| G | 原分辨率历史＋联合时域升采样 | 低分辨率残差的重建边界不稳，要求更精细输出 | 更多带宽；无新样本不能保证超分辨率细节 | 后续质量路线 |
| H | 改变降采样相位＋联合重建 | 采样网格导致的空间不稳定 | 非线性 NR 可能因相位变化更不稳定 | 研究路线 |

### A. 稳定区域检测＋无光流自适应 EMA

在同一屏幕位置比较当前输入与上一帧输入；只有局部亮度、颜色和边缘都足够稳定时，才混合该位置的残差历史。确定发生变化的位置直接使用当前残差。

```text
StableInput(p) 足够可信：H_t(p) = α R_t(p) + (1-α) H_t-1(p)
否则：                 H_t(p) = R_t(p)
```

实现成本低，适合固定镜头或低运动内容，也是衡量光流增量收益的对照。局限是颜色相近的物体移动可能绕过检测；没有明显颜色变化并不证明它还是同一个表面。对纹理不充分、边界或已知动态区域应保守处理。

其作用范围必须写清楚：这是一种静态区域稳定方案，不能宣称解决了运动中的时域闪烁。不能因为没有光流就全屏使用固定长历史。

### B. 光流重投影＋输入验证＋自适应 EMA

用原始颜色帧的光流把旧残差移到当前帧位置，再由输入一致性、匹配质量和历史状态决定权重。

```text
if !CanSampleHistory(metadata, motion, sampleDomain):
    Hnew = currentResidual
else:
    Hreproj = Warp(Hprev, currentToPreviousMotion)
    V = Validate(currentInput, warpedPreviousInput, motion, metadata)
    Hsafe = ConstrainHistory(Hreproj, currentResidual, historicalStatistics, V)
    Hnew = αeff * currentResidual + (1-αeff) * Hsafe
```

这里 `αeff` 是当前帧权重。历史无效时为 1；输入稳定但残差突变时可以较小；输入确认发生变化时应迅速增大。大运动本身不意味着历史一定无效，小运动也不保证可靠，判断重点是匹配质量和可见性。

这是最有希望作为通用主体的路线。运动向量只是历史位置的候选，验证必须独立存在。尤其不能只用 `abs(currentResidual - historyResidual)` 拒绝历史，否则需要抑制的 NR 自身波动会被误判成“应立即显示的新内容”。

时空降噪器已有“重投影、历史限制、自适应累积”的成熟构件；但针对阴影／反射的深度和法线规则，需要替换成 Magpie 能实际取得的颜色和运动证据。[AMD FidelityFX Denoiser 文档](https://gpuopen.com/manuals/fidelityfx_sdk/techniques/denoiser/)

#### B.1 单独生成判断用颜色引导图

把“判断历史是否对应当前内容”与“累积哪种信号”分开。由效果器原始输入 `X0` 生成轻度保边滤波的颜色引导图 `G`，保存上一帧 `G`；在运动补偿后比较局部图像块，估计历史可靠程度。最终仍累积未经这次空间预滤波的当前残差，避免判断用的滤波直接抹掉修正细节。

这是对原有输入验证的具体化，最值得优先加入 B。它不同于 E 中直接对残差进行空间降噪。引导图优先来自 `X0`，不使用自身会闪烁的 `XM` 或残差作为唯一依据；若光流来自更早的捕获输入，应先确认其与 `X0` 的坐标和内容变换兼容。

一个便于固定参数后复现的候选匹配规则如下；它是本项目的待测设计，不是上游原式：

```text
G_t = LightEdgeAwareFilter(X0,t)
if !CanSampleHistory(metadata, motion, sampleDomain):
    q = 0
else:
    GprevWarp(p) = G_t-1(uvPrev(p))            // only valid sample positions
    d(p) = mean over valid 3×3 patch of L1(G_t - GprevWarp)
    q = 1 - smoothstep(eAccept, eReject, d)   // 0 <= eAccept < eReject
```

每个 patch 位置使用自己的重投影坐标；跨运动边界或缺少足够有效样本时保守回退。`G` 的通道尺度、亮度／色度权重、预滤波范围、最低有效样本比例与两个误差阈值必须固定并记录，噪声容差应来自受控序列标定，不能直接把局部纹理方差当成已知噪声方差。`q` 是启发式权重，尚不是校准过的概率；当前 AMDOF 的常数 `0.65` 不能替代它。

先比较原始输入匹配与引导图匹配，只有前者因输入自身噪声频繁误拒绝时，才证明引导图增加的采样和存储值得保留。强预滤波可能掩盖遮挡、细线和真实光照变化；纹理很少、反射或同色物体处，匹配通过仍不证明历史正确。可额外检查未经平滑的边缘变化，但应单独测量它是否重新引入误拒绝。

运动补偿后做 patch 比较有视频降噪研究依据；完整 SPTWO 还包含相似块分组和 PCA，不能把上述轻量验证器称为其等价实现。[Video Denoising with Optical Flow Estimation](https://www.ipol.im/pub/art/2018/224/)

#### B.2 置信度只在一个明确的位置控制历史权重

首版优先使用已有时间常数，再乘一次匹配权重：

```text
wBase = exp(-Δt / τ)
wHistory = wBase * q
αeff = 1 - wHistory
Hnew = lerp(currentResidual, Hsafe, wHistory)
```

硬失效时先走当前残差分支，不读取或混合无效历史。固定更新频率下也可先试 `wHistory = wMax * q`；另一个会话提出的 `wMax = 0.75～0.875` 仅作为实验扫描范围。以每秒 60 次真实更新为例，约对应 `τ = 58～125 ms`；跨帧率比较时按时间常数转换，不能把固定权重原样套到所有帧率。这比一开始同时引入历史长度更容易定位置信度的作用，尚不证明画质一定更好。

有效历史长度是 B 的另一种权重策略，可以随后独立比较：

```text
N = min(Nmax, 1 + q * warpedPreviousN)
wHistory = 1 - 1 / N
```

这里 `N` 表示衰减后的历史量。传统 AMD 反射路径也采用匹配因子衰减历史量、再以 `1/N` 决定当前权重的结构；其几何匹配因子、粗糙度上限和阈值不能直接搬到 NR 残差。[AMD 固定版本重投影源码](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/blob/c6efa6bf7f2027b3ec94f28578bb5965eabb9e55/sdk/include/FidelityFX/gpu/denoiser/ffx_denoiser_reflections_reproject.h)

不要无解释地再改成 `wHistory = q * (1-1/N)`：当 `0 <= q < 1` 恒定且未触及上限时，`N` 稳态为 `1/(1-q)`，额外再乘一次会得到 `q²`，例如 `q=0.8` 时历史权重为 `0.64`。这种更强回退可以有意采用，但不是默认必须的设计，也不应将稳定效果变弱误归因于 EMA 本身。

#### B.3 历史插值前逐个验证采样点

另一个有价值的增量位于重投影采样阶段：双线性历史采样可能先把前景和背景混在一起，再通过颜色验证。传统 AMD 反射实现有按几何有效性排除 2×2 采样点、重新归一化插值权重的路径。[AMD 固定版本重投影源码](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/blob/c6efa6bf7f2027b3ec94f28578bb5965eabb9e55/sdk/include/FidelityFX/gpu/denoiser/ffx_denoiser_reflections_reproject.h)

Magpie 可尝试对四个候选历史位置分别检查有效域和颜色引导相容性，用双线性权重乘以各点接受度，再对有效点归一化；支持量不足时回退当前残差。**依据是颜色的近似判断，不能宣称具有 AMD 深度／法线验证的遮挡能力。** 部分点被排除会偏移有效采样位置，也可能切掉真实渐变；不得在很小的剩余权重上强行归一化放大一个不可靠点。

此项只在 B.1/B.2 后仍观察到运动边缘的跨物体泄漏时加入，并与直接拒绝整份历史比较。也可供 G 联合升采样复用。额外读取和分支需要计时，首版不同时叠加邻域搜索去寻找“颜色最像”的历史，以免在重复纹理中选错对象。

### C. 快慢两套历史＋变化确认

为同一残差维护快速跟随的 `Hfast` 与抑制闪烁的 `Hslow`。默认采用慢历史；当输入变化有证据，或新的残差状态持续存在并得到确认时，让慢历史向快历史靠近。

这能处理两个相反需求：短暂异常不要立刻出现，持续的新状态不能永远进不来。两个历史之间的差异仅表示状态有分歧，不单独证明真实变化。修正换位置本身就会造成快慢历史分歧，若立即切到快历史，闪烁又会回来。

建议加入有限的历史记忆时间和更新下限，避免稳定错误永久锁定；场景切换和明确遮挡仍立即清历史，不等待确认。NVIDIA NRD 使用 fast history 辅助较长历史响应，说明这是一类可借鉴结构；本项目采用的输入证据和阈值属于适配设计。[NRD 关于 fast history 的说明](https://github.com/NVIDIA-RTX/NRD#other)

### D. 短窗稳健累积：中值、截尾与异常值降权

普通 EMA 会让单帧强异常在未来多帧留下尾巴。可以在累积前，比较当前值与最近若干个已经对齐的历史观测，对孤立异常降权；三帧因果中值可作为小规模原型。

工程上有两种不同做法：

- 保存数帧真实残差并逐帧对齐，做中值或截尾均值。信息清楚，但保存和搬运多份历史，旧帧映射误差会累积。
- 只保存均值、方差与短历史，对离群创新量做有界更新。成本较低，但不等同于真实多帧中值，持续错误也可能污染统计。

按 RGB 通道分别取中值可能组合出不属于任何一帧的颜色。更稳妥的候选是依据亮度／色差评分对整个 RGB 样本统一加权。明确的输入变化、火花和闪光应绕过异常抑制，否则会误删真实瞬态效果。

当前只有当前到上一帧的光流。若使用三帧以上窗口，需要组合位移或搬运各历史面，并验证累计误差；不能把同一份一帧光流直接套到所有历史帧。

### E. 分频与方差引导的时空滤波

先区分空间低频修正与高频修正，再选择不同稳定强度。例如大面积明暗呼吸位于空间低频，细颗粒和轮廓抖动更多位于高频。不能一概认为“高频应该更强滤波”或“低频应该保留”。

一个可测的原型是：

```text
Rlow = EdgeAwareLowPass(R)
Rhigh = R - Rlow
Rstable = StableLow(Rlow) + StableHigh(Rhigh)
```

也可维护时间上的一阶／二阶矩，用方差估计局部不稳定程度；历史不足或匹配失败时，使用有限的边缘保留空间滤波帮助过渡。统计必须匹配残差的有符号数值，不能对原始残差直接套仅适用于正值辐射亮度的对数或归一化。

SVGF 的公开工作提供了“时间累积＋方差估计＋多尺度空间滤波”的依据。本项目能借鉴结构，但缺少它使用的几何引导，不能直接继承其质量结论。[SVGF 论文说明](https://research.nvidia.com/labs/rtr/publication/schied2017spatiotemporal/)

用原图颜色边缘指导滤波也有局限：NR 的光照修正可能跨过纹理边缘，颜色边缘不等于几何边界。过强引导会把原图纹理印入修正场，过弱引导则可能让修正跨物体扩散。

### F. 修正区域持续性与迟滞

同时估计某个位置“是否持续需要修正”和“修正幅度是多少”。可用残差幅度、方向和输入稳定性更新软置信度，对出现／消失使用不同的平滑速度，减少二值阈值反复跳变。

适用于“前几帧在 A 区域修改，后几帧在 B 区域修改”的现象。实际输出使用连续权重，避免硬开关；已有修正短暂缺失时缓慢衰减，输入改变或遮挡时立即取消旧权重。

不能同时对包含大量零值的残差做均值，再无条件乘以其出现概率：这可能对同一缺失现象重复衰减。应明确选择“无条件残差均值”或“出现概率×出现时的条件幅度”模型。

该路线会偏向持续修正，可能削弱本来就只出现一两帧的真实效果。仅凭残差频繁出现也不能判断其正确性，因此适合作为 B/C 的受限增强。

### G. 联合时域升采样

维护原分辨率残差历史，把当前低分辨率样本直接映射到高分辨率输出网格，同时完成历史验证和融合：

```text
Hfull,t = Reconstruct(lowResidual,t, Warp(Hfull,t-1), fullInput,t, validity)
Ot = baseFull,t + Hfull,t
```

可以同时减少残差闪烁并输出原分辨率修正，且不必每帧把历史重新压回低分辨率。保留原分辨率历史也能容纳运动带来的不同采样位置，但最终是否增加有效细节取决于样本与对齐质量。

没有 jitter 的版本仍然可以稳定和升采样；静止、固定网格、重复相同观察时，增加历史尺寸本身不会创造新细节。原图已有完整分辨率信息，也不代表低分辨率 NR 的细节修正已被恢复。

FSR2 展示了联合时域重建的通用方向，同时要求相应的运动、深度及渲染采样条件。此处更适合自行实现针对有符号残差的小型重建器，不能把普通 FSR2 的颜色输入替换成残差就预期正常工作。[FSR2 集成文档](https://gpuopen.com/manuals/fsr_sdk/techniques/super-resolution-temporal/)

### H. 改变降采样相位再累积

Magpie 有完整分辨率颜色帧，可以每帧以不同位置进行实际降采样，再将所得残差按已知相位放回原分辨率历史。只修改 SDK jitter 参数而不改变实际采样，不具备这一作用。

这可能减少固定网格造成的偏差，但 NR 对不同相位的响应是非线性的；不能保证这些输出只是同一个修正场的平移采样。还需要处理 NR 内部历史与相位变化的兼容性。若每层各自改变相位，串联误差会更难区分。

以减少闪烁为首要目标时，先保持固定采样。只有证明固定网格造成明显问题、且 B/G 已能可靠处理历史后，才比较短周期相位序列。不得以额外引入抖动作为首轮默认方案。

## 6. 可研究但不宜作为首版主体的方向

### 6.1 稳定前一层输出，再送入后一层 NR

潜在收益是降低 Pass 2/3 输入的时序变化，从源头减小后层波动。代价是外部历史开始进入后续模型，与模型自己的历史形成反馈；旧错误可能被后层继续强化，参数响应、首帧和失败恢复也更复杂。

应在纯输出稳定原型建立后单独 A/B，不能把“新增后处理”与“改变后层输入”放进同一次实验，导致无法解释收益来源。

### 6.2 光流预测并降低后续 pass 的执行频率

在跳过后层推理的帧上搬运旧修正，周期性用新推理更新。它可能省推理成本，但也可能产生周期性更新跳变，不能仅因画面变化变少就认为解决闪烁。不同 NGX 实例跨过若干捕获帧时，其模型历史和运动跨度还必须保持一致；当前一帧光流不能直接对应上一次执行的多帧间隔。

### 6.3 卡尔曼式增益或学习型视频稳定器

卡尔曼式滤波可用估计的不确定性调节增益，本质上仍依赖运动对齐、观测可信度与变化模型；NR 残差并不天然满足独立高斯观测假设。先做可解释的自适应 EMA，只有统计模型明显不足才增加这类复杂度。

学习型视频模型有更强表达能力，但需要适合有符号 NR 修正的数据、质量目标、训练或模型选择，以及额外推理预算。当前没有足够证据将它列为短期首选。

## 7. 所有时域路线的共同要求

### 7.1 正确对齐与历史有效性

当前运动单位是源像素。若源尺寸为 `(Ws,Hs)`，使用归一化坐标采样历史：

```text
uvPrev = uvCurrent + mvSourcePixels / float2(Ws, Hs)
```

若已经把 MV 缩放到低分辨率像素，则改为除以低分辨率尺寸；不能二次缩放。边界、裁剪区域、像素中心、资源世代与帧身份都要一致。引入实际采样相位时，还需完整定义相位坐标变换，防止重复补偿。

历史有效性至少考虑：越界、帧身份／尺寸、原图局部颜色差、梯度或边缘差、运动邻域是否混杂。颜色一致性要保留真实曝光和光照变化的响应，不能用过强归一化抹掉变化证据。透明、反射和相似纹理处无法仅靠颜色可靠识别遮挡，应保守降低历史。

前后向一致性可作为更强验证，但需要反向流或相应计算；当前接口只有一个方向，不应将它当作免费已有数据。共享捕获光流用于 NR 之前存在其他效果的输入时，也要确认尺寸映射和内容变换仍允许复用。

还要区分运动符号与运动场所在网格。若前向流满足 `y = x + Fprev(x)`，反向采样需要 `x = y + Bcurrent(y)`，则 `Bcurrent(y) = -Fprev(x)`，一般不等于 `-Fprev(y)`。只有同一当前网格对应关系的符号编码相反时，才能直接取负。上一时刻保存的反向流也不是当前这对图像的前向流；零 MV 只表示估计位移为零，不证明内容、曝光或反射没有改变。

### 7.2 历史限制不能把目标闪烁重新引入

如果当前残差在 3×3 邻域全部为零，而历史存在非零修正，严格把历史限制在当前 min/max 内会立即清掉修正。这样无法稳定“效果短暂消失”的闪烁。

候选策略是：输入稳定时放宽到含历史统计的区间，并设置有限保留时间；明确场景变化时直接重置；对真正的异常幅度单独设界。放宽范围会增加残留风险，必须和变化检测、有限衰减共同验证。

固定的 `μ±γσ` 还有另一种风险：压弱本来正确的细节。设 3×3 邻域只有中心具有稳定正残差 `a`，其余为零，当前与历史中心均为 `a`。则 `μ=a/9`、`σ=√8·a/9`；`γ=1.5` 时上界只有 `0.582516a`，若再以 `0.875` 历史权重混合，输出为 `0.634701a`。它变稳定的同时可能只是变弱；符号对称的负残差也有同类问题。这是隔离裁剪与混合的数值反例，不代表完整自适应滤波器的实际结果。

可把包含当前中心的方差区间或较宽 min/max 作为细节保护对照，但它们也会容纳当前异常点，且仍无法解决“当前残差暂时全零”的前述问题。`ClipAABB` 改变裁剪方向，并不会自动修复错误的允许范围。亮点保护、短暂缺失容忍与错误历史清除需要分别验收。

参数也应区分“允许历史偏离多少”和“保留多少历史”。在核对的 AMD 传统 Denoiser 1.3 版本中，`temporalStabilityFactor` 经 wrapper 传入 `history_clip_weight`，直接控制颜色裁剪范围；最终历史权重另由 `1−1/N` 决定。因此不能解释成“设置为 0.9 就保留 90% 历史”。[AMD 固定版本时域融合源码](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/blob/c6efa6bf7f2027b3ec94f28578bb5965eabb9e55/sdk/include/FidelityFX/gpu/denoiser/ffx_denoiser_reflections_resolve_temporal.h)

### 7.3 时域平滑有响应代价

对常数真实信号叠加独立、零均值、同方差噪声，固定当前帧权重 `α` 的 EMA 在稳态下有：

```text
输出噪声方差 / 输入噪声方差 = α / (2-α)
阶跃响应达到 90% 所需更新次数 = ceil(log(0.1) / log(1-α))
```

| 当前帧权重 α | 理想噪声标准差比例 | 90% 阶跃响应更新次数 | 60 次真实更新/秒对应时间 |
| --- | --- | --- | --- |
| 0.1 | 0.229 | 22 | 367 ms |
| 0.2 | 0.333 | 11 | 183 ms |
| 0.3 | 0.420 | 7 | 117 ms |
| 0.5 | 0.577 | 4 | 67 ms |

这些是数学模型结果，不是 NR 画质预测。真实残差可能存在自相关、偏差与慢漂移，不能宣称按表获得同等降噪比例。自适应权重和硬重置正是为了减少真实变化的响应延迟。

历史建议按真实时间常数定义，例如 `α = 1 - exp(-Δt/τ)`，再由有效性控制；不要以补帧后的显示 FPS 设置历史长度。这里增加的是修正响应滞后和计算时间，因果滤波不要求等待未来帧，不等于额外缓存数帧后才显示。NRD 也明确区分真实渲染帧率与补帧帧率。[NRD 帧生成注意事项](https://github.com/NVIDIA-RTX/NRD#interaction-with-frame-generation)

`Nmax=8` 不是只保留最近八帧：固定系数 EMA 的更早历史仍持续衰减。在上面的理想噪声条件、没有裁剪且历史权重固定 `w=0.875` 时，方差等效样本数为 `(1+w)/(1-w)=15`，旧信号半衰期约 `5.19` 次更新；它们分别衡量方差和响应，不是额外保存了 15 张图，也不是实测降噪收益。

### 7.4 历史更新、重置和失败

- 只在新的、成功完成的捕获帧上推进历史；重复显示与参数重合成不增加样本数。
- 同一捕获帧的上游或本层参数变化要使相关历史失效，或走明确的重新初始化流程，不能把新旧参数结果混合。
- 场景切换、捕获来源／区域／尺寸变化、设备重建、长停顿、颜色域改变、pass 数变化及推理失败，都要按影响范围重置。
- 先计算候选历史，整条链成功后再发布其有效状态；失败输出不能写成下一帧可信历史。
- 首次没有历史时，从当前残差初始化；“从零渐显”是另一种可选效果，不能无意引入。
- 光流必须对应实际积累的相邻帧；若中间帧只更新了 provider、没有更新残差历史，需要重置或正确组合位移。
- 采样前检查历史存在性、运动有限值和采样覆盖域；`clamp` 地址模式不能使越界历史有效。颜色、统计或历史出现 NaN/Inf 时显式走失效分支，不能期待 `0 × NaN` 或零权重的 `lerp` 自动清除污染；当前残差本身非有限时，使用明确的上游失败／有效基准图回退，停止发布候选历史。
- 所有拒绝路径先初始化输出和有效状态；reset 同时使残差、引导图、矩／长度与快慢历史等关联资源失效。只清颜色或某张平均值纹理不等于完整重置。

### 7.5 颜色与参数语义

历史保存有符号浮点 RGB 或明确定义的线性色彩变换；不要对有符号残差本身使用 `saturate`，也不要直接平均环形 HSL Hue。最终颜色范围按输出格式限制，Alpha 沿用基准图的约定。

当前 SDR 控制在存储编码值上运算，并仅在方向分类时转换到线性亮度。首个兼容原型宜沿用这一差分域；若改用线性光残差，应明确记录它改变了度量和合成行为。HDR 不能沿用 SDR `[0,1]` 裁切与阈值。

把累积放在 `ApplyResidualControls` 之前可让参数即时作用于稳定的原始残差，但非线性的方向分类和 HSL 可能重新产生跳变；放在其后更贴近实际输出修正，却需要在参数修改时重置相关历史。初版优先分析实际输出差分，再决定是否优化到控制之前。

### 7.6 重复重投影、HUD 与已有时域处理

双线性反复搬运历史会累积子像素模糊，即使 MV 正确也要测试细线及棋盘格持续平移。更高阶插值可能减少模糊，同时引入过冲或振铃；不能靠换采样核承诺消除闪烁。这里主要影响 NR 修正细节，因为基准图每帧仍来自当前帧。

Magpie 捕获输入可能已经做过游戏 TAA/DLSS 并包含 HUD，不能假设拿到 UI 合成前的画面。屏幕固定文字和移动场景可在同一邻域产生不同运动；从最终颜色估计光流不能保证拆开二者。没有可信 UI 掩码时应纳入测试和局部保守回退；已有 NR UI correction 不自动提供可供外部稳定器使用的逐像素掩码。外部历史也会叠加输入与模型原有的响应滞后。[TAA 综述](https://research.nvidia.com/labs/rtr/publication/yang2020survey/)将历史验证与样本累积分开讨论，本方案也应分别观察两者的失真。

## 8. 与当前 Multi Pass 的三种接入方式

### 8.1 原分辨率最终差分：最清楚的验证入口

在 `DLSSNRMultiPass::Draw` 完成现有串联后，计算 `Rextra = XM - X1`，过滤后加回当前 `X1`。如果要处理总残差，改为 `XM - X0`。模型各层的原有输入不变，关闭稳定器直接输出现有结果。

需要额外的差分／历史纹理、输入历史和最终合成目标，不能把同一个资源同时作为不允许重叠的 SRV/UAV。只展示稳定后的输出，原始 `XM` 仍可留作下一次诊断或旁路。

这条路线直接包含了各层裁切、参数及量化后的真实变化，适合先验证“应该滤什么”。代价是工作在原分辨率。

### 8.2 低分辨率残差历史：有条件的性能路线

两种办法需要分别看待：

**从最终差分提取低频。** 令 `r = D(Rextra)`、`e = Rextra - U(r)`，则：

```text
Ot = X1,t + e_t + U(Stable(r_t))
```

忽略数值舍入时，`Stable(r)=r` 可回到 `XM`；正式关闭仍直接旁路，避免额外舍入。这保留当前帧高频补偿 `e`，但 `e` 中的闪烁也会留下。适合以低频明暗呼吸为主要问题的场景；不能宣称稳定了全部残差。重新计算 `e` 和全分辨率合成也有成本。

**暴露各层内部低分辨率 `ControlledResidual`。** 在现有插值前加入历史，可直接沿用 Catmull-Rom 回到原分辨率。但是一旦稳定后的输出成为下一层输入，就属于反馈式串联；若只在末端使用这些残差，则要显式处理各层完整输出裁切、参数和缩放之间的关系。

不能直接认定 `XM-X1 = U(C2+C3)`：即使缩放核相同且线性，层间裁切和量化也会破坏等式。需要证明或记录近似误差，保留饱和高光、阴影和彩色边缘的对照。

### 8.3 所有 NR 在统一低分辨率连续执行

```text
I → D → NR1 → NR2 → NR3 → 提取残差 → 稳定／升采样 → 加回 I
```

它能减少反复缩放和部分资源往返，也便于只提取首层／末层低分辨率结果。但它与当前每层都处理完整合成图的逻辑不同，共享 Detail Control 在各层生效的含义也会改变。

这是可行的另一种产品模式，应独立比较画质与成本，不能包装成现有串联的无行为变化优化。本轮不以重构 Multi Pass 为减少闪烁的前置条件。

## 9. 成本与测量

以下只计算保存残差的两张 `RGBA16F` 乒乓纹理，不含输入历史、快慢历史、方差、掩码、对齐、临时纹理、驱动分配开销和模型自己的历史。

| 历史尺寸 | 像素数 | 单张 RGBA16F | 两张 RGBA16F |
| --- | --- | --- | --- |
| 960×540 | 0.518 M | 3.96 MiB | 7.91 MiB |
| 1280×720 | 0.922 M | 7.03 MiB | 14.06 MiB |
| 2560×1440 | 3.686 M | 28.13 MiB | 56.25 MiB |
| 3840×2160 | 8.294 M | 63.28 MiB | 126.56 MiB |

最简单的当前残差读取、历史读取、结果写回，逻辑数据量约为每像素 24 字节；720p 为 22.12 MB/帧，1440p 为 88.47 MB/帧。它不等于实际显存事务量，真实成本还受纹理缓存、重投影采样、邻域统计、dispatch 和同步影响。

1440p 的 50% 宽高对应 720p，像素数是 25%。540p 对应 37.5% 宽高，像素数约 14.1%；当前输入百分比是整数，37.5% 不是可直接选择的现有参数值，表内 540p 作为分析尺寸。

需要分别记录：

- 每层 NR GPU 时间，以及降采样、残差准备、升采样和外部稳定器 GPU 时间。
- OF 的 GPU 时间、调用前后资源同步和等待；AMDOF 当前 `opticalFlowSubmit` 等日志是 CPU 提交区间。
- 整条链完成时间及 p50/p95/p99，观察与游戏竞争资源时的变化。
- GPU 显存峰值及 pass 数、历史分辨率改变后的增量。
- 同一基线是否已经启用同配置的光流；已有光流可以共享，首次为稳定器启用光流则需要计入其成本。

若 NR 本身使用当前帧同一份光流，则存在 `OF → NR` 的真实依赖，不能只把等待挪到最后就与全部 NR 重叠。只有 NR 不依赖该 OF 的分支，才可能在保证输入和资源生命周期正确后并行；并行仍可能因资源竞争拖慢 NR。

对话中的“新增 0.x ms”“OF 完全隐藏”仅是条件估算。本项目是否达到这些数量级，必须由新增 GPU 时间戳及整帧测量决定。

## 10. 实验与路线选择

### 第一阶段：定位和最小可用比较

准备固定输入序列和相同初始历史，保留 `X0`、`X1`、`XM`、总残差、额外残差，以及可取得的原始／受控低分辨率残差。冻结输入实验通过专用重放路径推进测试帧身份；生产重复帧缓存可能跳过推理，不能仅看冻结窗口的稳定画面就认为模型稳定。

比较以下模式，使用相同 NR 参数、pass 数和分辨率：

1. 单层 NR；现有 Multi Pass；适当降低后层强度的 Multi Pass。
2. 原分辨率总残差与额外残差的无光流稳定区域 EMA。
3. 相同残差对象，加入当前可用共享光流和独立历史有效性判定。

这一步回答三个问题：首层是否也需要稳定，光流是否带来足够的运动收益，降低后层强度能否以更简单方式达到类似观感。

对 B 的增量再单独比较：原始输入验证／B.1 轻度引导图验证；固定时间常数乘一次 `q`／B.2 历史长度控制。先使用相同插值和历史限制，保存 `q`、有效域、裁剪前后残差、裁剪距离及最终权重图；不能同时更换所有模块后只比较最终画面。B.3 逐采样点验证放到边缘泄漏确认之后。

### 第二阶段：只针对剩余问题增加机制

| 第一阶段剩余问题 | 优先增加 | 不宜直接采用 |
| --- | --- | --- |
| 静止仍有修正区域反复出现／消失 | C 快慢历史，必要时 F 持续性 | 无限延长单套历史 |
| 单帧亮暗点进入历史后残留 | D 稳健更新 | 全屏强空间模糊 |
| 边缘附近细颗粒和大块明暗抖动并存 | E 分频／有限空间滤波 | 所有频段同一强度 |
| 动态区域大面积拒绝历史 | 先验证 MV 坐标、置信度和输入匹配 | 直接放宽历史接受条件以强行增加历史 |
| 低分辨率稳定有效但上采样边界仍不稳 | G 联合重建 | 立即引入 H 相位扰动 |
| 开销主要在全分辨率历史 | 8.2 低频历史或明确的低分辨率接口 | 未验证等价性就重构全部串联 |

### 第三阶段：验收维度

覆盖静态人脸／墙面、慢平移、快速转镜、前景遮挡后移开、细线／文字、粒子／闪光、镜面反射、昼夜／曝光变化、场景切换、暂停恢复、重复捕获、实时参数调整与 pass 数切换。

新增合成验收顺序：静态无噪声正／负孤立残差点（不能被持续压弱）→ 已知幅度及均值的时间扰动 → 精确整数／子像素平移 → 人为加入 MV 误差及非均匀运动 → 遮挡显露及 HUD。另保留“原图稳定、修正短暂归零”素材，确认细节保护没有使历史限制重新恢复开关闪烁；对非有限值与无效采样域进行故障注入，确认不会污染后续历史。

必须同时观察：

- **闪烁**：在确认输入稳定或可靠对齐的区域，统计残差时间标准差、帧差和高分位异常幅度；亮度与色度分开记录。
- **修正保留**：检查长期平均修正、幅度、作用面积、局部对比度和 NR 特征。时间均值只能作诊断参考，不能充当画质真值。
- **响应与拖尾**：真实变化后旧修正的残留幅度、面积和持续毫秒数，特别是运动后的黑斑／光晕。
- **空间质量**：边缘宽度、跨物体泄漏、过冲、纹理被抹除以及不稳定细节是否只是被压弱。
- **开销**：新增计算、总处理链尾部时间、尾延迟分位数与显存。

不能以“输出变化减少”单独判定成功：输出全零残差也能消灭残差闪烁。应把候选方案与降低 NR 强度、减少 pass、温和空间滤波的对照放在一起，以相近的可见修正强度比较稳定性。

可复现的合成平移素材使用已知位移评估运动区域，避免只用被测光流评价自身效果。实际录像则固定 ROI、说明对齐的不确定性，并保留视频主观比较。对帧差指标使用独立的场景有效性掩码，不能只统计算法自己愿意保留历史的容易区域。

进入下一阶段的依据是：在保持可接受修正和响应的前提下，闪烁确有改善；额外复杂度能解决已观察到的问题。具体画质门槛和毫秒预算在第一阶段测量后确定，避免把理论估算当作验收结果。

## 11. 本次路线结论与待对齐项

**优先路线是 B，保留 A 作为低成本模式和对照；C 最值得作为后续增强。D/E/F 按闪烁形态选择，G 用于确有联合升采样需求时，H 暂缓。**

首个原型采用当前串联完成后的有符号输出差分，优先观察后续 pass 新增残差，并与总残差累积比较。原分辨率原型可避免误把重构收益当成滤波收益；低分辨率优化在确认目标信号后推进。

本次交叉 review 进一步明确 B 的首版：输入引导验证与残差累积分离，先采用一个明确的历史权重控制点，并通过第 7.2 节的细节／缺失反例约束历史保护。B.3 是出现边缘泄漏后的可选增强；有效历史长度作为另一种权重策略比较，不与所有新模块一次性叠加。主路线优先级不变。

后续实施前需要确定的是产品取舍，而非算法名：允许多少修正响应延迟、首层是否需要稳定、无光流模式是否作为正式选项，以及优先保留现有 Multi Pass 行为还是增加统一低分辨率新模式。当前文档不预设这些选择已经获批。

## 13. 068 local 首版实施：A / B

2026-09-14 用户确认本会话实现 A、B 并部署到 `0.6.8-local`；F、G 留到后续会话。第二列 Multi Pass 后增加“抗闪烁”：`无 / A · 静态累积 / B · 光流累积`，对应持久化键 `antiFlicker=0/1/2`，缺省关闭。当前没有 F/G 占位选项。

### 已实现的取舍

- 单层累积 `X1−X0`，多层累积 `XM−X1`；统一放在全分辨率输出端，不改变 NGX 的各层输入或内置历史。输出加回当前基底，SDR 最后限制到 `[0,1]`，保留最终原始输出 alpha。HDR 在本来的浮点域累积有符号残差，不套 SDR 饱和限制。
- A 在原屏幕位置匹配 3×3 原输入；B 对每个 patch 位置使用自己的当前到上一帧光流。B 首版采用 B.1 的“未预滤波原输入”对照版本，未加入颜色引导预滤波、B.3 的逐 tap 验证或邻域搜索。原输入历史与残差历史独立保存。
- B 复用现有光流请求；如果 NR 未选光流，则外部稳定器请求 AMDOF Quality。NR 原参数仍保持原语义。光流服务会统一选择提供器，并通过现有 consumer adapter 对齐尺寸和向量尺度；稳定器只接受匹配当前效果尺寸和帧 ID 的 CurrentToPrevious / SourcePixels 资源。失效或零光流回退静态匹配，切换时重置；提供器初始化失败仍由原服务处理。
- 验证颜色使用 SDR 原值；HDR 使用 `c/(1+abs(c))` 压缩后的有符号颜色。patch 误差为每点 RGB 最大绝对差的均值，`qMean=1−smoothstep(0.008,0.04,error)`；再乘 `qMax=1−smoothstep(0.025,0.10,maxError)`，保护小范围真实变化。必须有完整 3×3 支持；B 的邻点光流与中心任一分量差超过 2 像素时拒绝该 patch。这些是固定的首版调参值，并非已标定概率。
- 使用 B.2 的时间常数策略：`w=exp(−Δt/0.08)*q`，不再乘提供器的固定置信度。按真实捕获时间更新；缺少有效元数据、时间倒退、250 ms 以上间隔、资源代际／有效域变化和显式重置时直接用当前残差。B 另保守拒绝不连续的 frame ID，避免把单步光流当成跨多步历史映射。
- 历史限制使用包含当前中心的 3×3 残差 min/max，逐通道扩展量为 `0.02+q*abs(history)`。输入稳定时允许已经消失的修正按 EMA 衰减，避免固定紧盒立即清掉“有／无”历史；输入不匹配时立即放弃历史。没有快慢历史或持续性判定，因而不能等同 C/F。
- 重投影前检查完整采样域及有限运动向量；颜色和残差历史 alpha 作为有效标记。无效当前值不写入有效残差历史。逻辑重置后直接写入整帧新的残差和颜色，不读取旧历史；重复捕获帧保持索引与时间不变。即时参数编辑会使整个外部历史失效。

### 成本和边界

额外分配一个原格式最终输出中间纹理，以及两张残差和两张输入引导历史（均为 RGBA16F）。在 SDR RGBA8、2560×1440 下，纹理有效载荷约 126.56 MiB；3840×2160 约 284.77 MiB，不含资源对齐、视图、光流及原有 NR 资源。关闭选项不创建这些资源。

每个像素执行邻域颜色验证及残差范围统计，B 再读取光流与插值历史。尚未测得真实硬件 GPU 耗时，不能用 WARP 测试时间代替。重复重投影可能变软，同色遮挡可能漏判，NR 中已存在的错误结构或 Pass 1 闪烁也不能保证消除。G 的联合时域升采样及 F 的持续性/迟滞均未实现。

### 验证与交付定位

实现与使用说明见 [DLSSNR Multi Pass](../effects/DLSSNR-MULTIPASS.md)。专项测试执行生产 HLSL 的软件 D3D11 WARP dispatch 与生产时间状态；覆盖有符号修正、开关衰减、输入变化、非有限值、孤立细节、已知运动、错误匹配、越界和均值/方差。处理链测试覆盖单层与三层接入、缺省关闭、路线解析、光流请求、参数重置；这些不等于完整 NGX 游戏验证。

部署沿用 `scripts/Deploy-Local068.ps1`；是否已完成以 `release/v0.6.8-local/deployment-state.json` 与程序目录的 `build-manifest.json` 为准。后续优先在固定游戏片段中比较“无 / A / B”的闪烁、修正强度、拖影和 GPU 开销，再分别评估 F 与 G。

## 14. 068 local 扩展实施：F / G

2026-09-14 后续会话按用户要求继续实现 F、G，以 A/B 提交 `093efe21` 为实现基线。本节取代第 13 节中“F/G 未实现”的阶段状态。抗闪烁下拉框现在为 `无 / A · 静态累积 / B · 光流累积 / F · 持续性迟滞 / G · 时域升采样`，持久化值依次为 `0/1/2/3/4`。不改旧配置，不新增组合选项。

### F：条件幅度与软持续性分开保存

继续使用单层 `R=X1−X0`、多层 `R=XM−X1` 的全分辨率差分。F 使用 B 的光流与 3×3 输入匹配，维护条件幅度 `A` 和连续支持度 `P`，显示修正为 `P*A`。历史 RGB 保存 `A`，alpha 保存 `1+P`；alpha 为零表示无效，因此不需要新增历史纹理。匹配颜色域沿用 SDR 原值、HDR 的 `c/(1+abs(c))`。

定义本帧软观察 `s=smoothstep(0.005,0.02,maxRGB(abs(Guide(raw)−Guide(base))))`。这两个阈值衡量输入／输出颜色修正幅度，属于实验参数，不是修正真实性概率。强修正的 `s=1`；弱修正可能被门控削弱。

在通过输入和历史有效性检查的像素：

```text
w80 = exp(−Δt/0.08)
τsupport = s > Pprev ? 0.06 : 0.18
wSupport = exp(−Δt/τsupport)*q
Pnew = lerp(s, Pprev, wSupport)
Anew = lerp(Constrain(Aprev), R, (1−w80*q)*s)
output = base + Pnew*Anew
```

当 `s=0` 时，条件幅度不混入零值，只衰减 `P`。因此不存在“先将缺失值平均成较小残差，再乘出现概率”的重复衰减。输入匹配权重 `q` 在每条状态的时间权重中只出现一次。沿用包含当前中心的历史范围保护；这里保护的是条件幅度。

特殊分支：旧支持度不超过 0.001 时直接以当前幅度建立新的条件幅度；当前修正与旧幅度点积为负时，旧方向立即取消，新方向以 60 ms 出现速度重新建立支持。首次观察、输入不匹配、无效历史和全局 reset 直接建立 `A=R、P=s`，不等待旧状态慢慢退出。全局生命周期、重复帧和参数修改规则与 B 相同。

F 有意采用快出现、慢消失。它可能提高反复出现区域的平均修正，相对 B 不要求保持时间均值；也可能削弱短暂或弱修正。持续存在且 `s=1` 的无噪声正负修正应恢复到全幅，持续缺失则应退出。这是持续性迟滞，不是 C 的快慢两套颜色历史，也不判断模型修正是否正确。

### G：低频观察的联合时域重建，保留当前高频补偿

首版明确选择第 8.2 节的“从最终差分提取低频”接口，并按 G 保存原分辨率历史。没有暴露 NGX 内部 `ControlledResidual`，也没有将所有 NR 改成统一低分辨率串联。这样可以保留现有各层控制、裁切、量化及输入行为。

每个真实新帧先以 2×2 有效像素均值生成半分辨率有符号残差观察 `r=D(R)` 和原输入颜色引导 `g=D(Guide(X0))`。宽高向上取整；奇数尺寸最后一行／列只使用实际存在的样本。固定约 50% 宽高独立于 NR 输入分辨率百分比，因此不开启 NR 降分辨率时也可以测试 G。

随后在原分辨率输出网格执行一次联合重建 dispatch：

```text
C = GuidedUpsample(r, g, Guide(X0))
e = R − C
Hfull = lerp(C, Constrain(ValidatedWarp(HfullPrev)), w80*q)
output = base + e + Hfull
```

`C` 使用四个低分辨率样本，其双线性权重乘以颜色接受度 `1−smoothstep(0.02,0.10,maxRGB(abs(Guide(X0)−g)))`，剔除非有限／无效样本，再归一化；总支持量小于 0.05 时直接输出本帧 raw 并使该处残差历史失效。采样位置按实际 2×2 块中心计算，奇数边缘使用截短块中心。提取阶段遇到有效域外或非有限样本时整块标记无效，避免将故障平均进低分辨率观察。

历史保持完整输出尺寸，不每帧降回低分辨率。沿用 B 的逐 patch 重投影和原输入验证，额外在历史双线性插值前验证四个 tap：逐点有效域、有效标记、有限值及原输入颜色相容性，颜色接受区间为 0.025～0.10；剩余权重不足 0.25 则拒绝历史。此处采用 B.3 的受限颜色验证构件，不具有深度／法线遮挡判断的能力。

`e` 是以同一次重建定义的精确当前补偿，不进入历史。关闭历史融合时 `base+e+C` 回到原始串联结果，孤立正负修正和细线无需依赖低分辨率观察恢复。正式选择“无”仍完全旁路。**这也限定了本版 G 的覆盖范围：主要稳定低频修正，高频补偿内的闪烁仍会直通。** 它是带细节补偿的联合残差重建，不等于对全部残差做 TAAU，更不保证超分辨率细节。没有 jitter；没有减少 NR 推理或各层原有升采样的开销。

### 共用接入、资源与边界

- F/G 都复用现有光流；未选择光流时为外部稳定器请求 AMDOF Quality。无效或零光流切回静态匹配并清历史，提供器启动失败沿用原光流服务规则。单步光流只用于连续帧；间隔、尺寸、代际、有效域、输入修订和参数变化会使全部相关状态重置。
- F 的资源有效载荷与 B 一样。G 额外增加两张半分辨率 RGBA16F 观察纹理；偶数尺寸比 A/B/F 多约 4 字节／原分辨率像素。SDR RGBA8 下，完整额外纹理合计约 140.63 MiB（2560×1440）、316.41 MiB（3840×2160），不含光流、对齐、驱动和 NR。所有路线关闭时均不分配外部历史。
- G 增加一次半分辨率提取 dispatch 和原分辨率重建中的采样；F 增加持续性算术。尚未测得硬件 GPU 耗时。WARP 只用于正确性验证，不能用于推断实时性能或 NGX 游戏画质。
- 有符号残差和条件幅度仍存 RGBA16F；HDR 最终限制为有限 FP16 范围，SDR 最终限制为 `[0,1]`，保留 raw alpha。相似颜色遮挡、HUD、反射、输入中已有时域处理的拖尾仍是共同限制。
