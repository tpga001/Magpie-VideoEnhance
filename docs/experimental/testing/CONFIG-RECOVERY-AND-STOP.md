# 0.6.7 配置恢复与停止缩放

## 配置恢复

启动时检查 JSON、配置结构、效果缩放类型、数值范围、配置与效果组索引，以及已安装效果的参数范围和枚举选项。

- 已知旧版本设置继续交给现有迁移器处理；迁移前也保留原件。
- 失效参数使用当前默认值，其余参数和效果组保留。损坏的效果链仅将该组恢复为 Lanczos，并保留组索引，避免其他应用配置指向错误的组。
- 用户主动创建的空效果组保留。缺失效果文件、未安装 SDK、未知扩展参数不触发整份重置；启动效果时仍使用对应错误引导。
- JSON 损坏时依次尝试备份、完整可恢复条目；均不可用时生成默认设置。
- 原件与恢复结果分别保存在配置目录中的 `config.json.recovery-v1-….original` 和 `.json`。同一份原始内容复用已经完成的恢复结果；比较完整原件内容后才允许复用，文件名散列不承担安全校验功能。
- 保存恢复结果后才替换活动配置；写入失败时保留原件与结果，用户修复文件权限、占用或磁盘空间后重新启动即可继续。
- 恢复记录本身不可用时提示用户从原件或其他备份恢复，避免反复自动重置。
- 启动通知区分迁移/局部修复、备份恢复、部分恢复和默认值重建，包含原件位置及修复字段路径，并提供配置目录入口。

## 停止缩放

工具栏最右侧 × 的左键动作是停止缩放。

2026-09-07 07:05 的 0.6.6 转储显示，`CursorManager::_SrcHitTestAsync` 恢复后进入 `_UpdateCursorState`、`_ClipCursorForMonitors`，访问了空 `Renderer`。停止时清理叠加层状态可能重新发起光标查询；原先查询在发起时读取全局 RunId，可能在旧对象即将销毁时取得更新后的编号。

修复包括：

1. 光标管理器固定持有创建时的会话取消标记；显式销毁窗口和系统触发 WM_DESTROY 都先发布取消。
2. 清理叠加层时仍清除输入标记，但取消后的光标管理器不再发起捕获、命中测试或位置更新。
3. 异步查询返回时先检查仍存活的取消标记，再检查窗口、渲染器和当前光标对象，最后才访问原对象；关闭中的调度队列失败也正常结束查询。
4. × 仅记录停止请求，在输入和绘制回调返回后的外层循环执行销毁。重复请求合并，窗口销毁或重新启动时清除旧请求。
5. 销毁过程中停止向叠加层派发输入，并防止重复进入销毁流程。

另一个历史转储的堆损坏不能由以上堆栈确定根因，此修复不声称解决所有历史崩溃。
