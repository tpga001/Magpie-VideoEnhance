# 0.6.7 参数面板双路径验收

“参数调整焦点切换”位于“配置文件 → 高级”尾部。默认配置及每个应用配置各自保存“参数调整焦点切换”，字段为配置对象内的 `parameterFocusSwitching`。下一次会话使用匹配应用配置的值，未匹配应用使用默认配置；运行中修改不会切换现有输入通路。旧全局值迁移到已有配置，单独设置优先；保存后删除全局字段，因此不会重复覆盖。新配置（包括从其他配置复制创建）默认关闭。

## 默认关闭：基于 0.6.6 的交互

参数面板只有显示／关闭。打开后直接通过原缩放窗口和 ImGui 鼠标队列操作，标题栏关闭按钮保留。点击游戏区域不进入只读预览；不创建参数输入宿主，不获取前台焦点，不接管 Esc，也不启用参数键盘输入。重新启用后恢复面板显示、位置和大小。

## 开启：完整焦点切换

启用说明：“参数实时调整时启用焦点切换，但在部分窗口上运行时可能不稳定。”以下独立宿主、编辑／预览、键盘和 Esc 逻辑仅在开启后使用。

实时参数面板分为关闭、编辑和预览。工具栏不获取游戏焦点；打开参数面板进入编辑，鼠标脱离 Magpie 的游戏捕获和坐标映射。单击游戏区域时，本次按下和松开全部由参数层接收，随后返回游戏并保持只读预览。标题栏、下拉选项列表和已开始的拖动均属于参数交互区域；移出面板不会退出编辑。

工具栏参数按钮与默认 `Alt+Shift+E` 使用同一面板开关：关闭时打开并进入编辑；编辑或预览时触发则关闭面板。快捷键可在首页工具栏设置中修改。参数按钮在编辑和预览时均保持选中；工具栏和参数标题栏均不另设关闭按钮。`Esc` 先关闭下拉菜单或数值输入，随后按“编辑 → 预览 → 关闭”逐级退出。编辑时单击游戏区域保留预览；预览时单击参数面板（含标题栏和子区域）直接返回编辑，并将同一次点击交给参数控件，可直接拖动滑条、切换开关或打开下拉菜单，按下／松开不传给游戏。预览面板以外仍可正常操作游戏。切到其他应用立即取消输入接管，沿用原有窗口／全屏切屏规则。

`Ctrl+单击` 滑条可直接输入参数数值。输入使用实际参数单位，按声明的步长归一化并限制在范围内；普通拖动继续使用离散步数。例如步长为 0.05 时输入 0.73，会应用 0.75。

工具栏悬停提示统一为“按钮名”或“按钮名（当前快捷键）”，不附带操作或状态说明。固定、性能分析、实时参数、对比、截图使用对应绑定；切换模式使用目标模式的快捷键，停用使用当前模式的快捷键。修改或清除绑定时同步更新，最小化与演示窗口没有绑定则只显示名称。

## 实现及自动验证

- 使用 `WS_EX_NOREDIRECTIONBITMAP` 的可激活输入宿主覆盖渲染区域，保持原有 ImGui 绘制。原生原型验证透明像素、整窗命中、激活、解除光标限制、首击完整交接和后续游戏点击。依据：[Microsoft Windows Composition 文档](https://learn.microsoft.com/en-us/archive/msdn-magazine/2014/june/windows-with-c-high-performance-window-layering-using-the-windows-composition-engine)。
- 预览在 ImGui 内保持只读，使用仅覆盖最后成功呈现的面板范围的原生宿主接收激活点击；显示该区域不会获取焦点。点击时激活宿主并扩展至渲染区域，在 NewFrame 前恢复面板输入标记和命中信息，按原始屏幕坐标将首击交给控件。区域随成功呈现更新并裁剪到渲染范围，呈现失败不提前移动命中区域。编辑时使用宿主鼠标捕获维持越界拖动。鼠标、键盘、字符和取消事件经过现有输入队列，无游戏新帧时沿用缓存画面的叠加层刷新。
- 预览时的普通 `Esc` 经现有缩放线程键盘钩子接收，仅在游戏／缩放窗口前台时接管首次按下、重复和松开。松开后由外层循环关闭，不在钩子中修改 ImGui 或焦点；其他应用、系统组合键及已经按住的 Esc 不被接管。状态变化或切出应用会取消待执行关闭。
- 参数宿主被识别为缩放内部窗口。编辑优先于 3D 模式锁鼠，缩放窗口不主动抢回焦点。激活和返回游戏前再次检查当前前台窗口；失败显示“请点击游戏窗口恢复控制”，不循环激活。
- 缩放窗口和参数宿主共享同一个状态路由，均处理预览激活、面板外退出和按下／松开配对。命中判断采用 `GetMessagePos` 的消息屏幕坐标；延迟处理时不会误用已经移动的当前光标位置。继承自激活前窗口的修饰键单独记录，物理松开后清除；宿主实际接收的按键仍等待完整松开。
- 预览范围使用成功呈现的边界参与光标捕获交接。该处理在 3D 锁鼠分支之前运行，先将被映射的游戏光标还原到显示位置；光标离开面板或切到外部应用时，继续原有游戏捕获路径。
- 主动停止、手动／自动参数重建、切换缩放模式，以及源窗口变化导致的重建，都等待参数层接收完尚未松开的输入。停止之后释放捕获、光标限制和宿主。游戏已关闭或用户切到外部应用时立即清理，尊重新焦点。
- 重建保存面板位置、大小及编辑／预览状态，并保留已经请求的返回游戏或关闭状态。窗口移动和 DPI 变化更新宿主范围、面板布局及缩放。
- 参数快捷键通过 `RegisterHotKey`／`WM_HOTKEY` 触发，保留系统热键的输入入口及 `MOD_NOREPEAT` 防重复行为。低级键盘钩子不再抢先吞掉参数热键。其他快捷键沿用原来的双路处理。预览 Esc 仍只在接管首次按下之后接管重复和松开，避免只吞松开造成不成对输入。

执行 `tests/Run-ParameterInputTests.ps1` 可编译并运行提取自生产实现的输入与布局测试。`-NativePrototype` 额外创建两个测试窗口，验证真实 USER32/DWM 行为，结束后恢复原光标和焦点。

自动回归分别覆盖默认路径的直接首击、滑条拖动、下拉关闭、游戏区域继续输入、Esc 不接管、标题栏关闭、恢复显示及零宿主／零激活；配置回归覆盖默认、缺失、错误类型和开关双向保存重载。开启路径覆盖三态、预览首击直接拖动滑条／切换开关／打开下拉菜单和子区域恢复编辑、面板外游戏输入、失败呈现命中范围、首击成对交接、滑条拖出边界、下拉区域、数值键盘输入、Esc 逐级退出及长按／组合键／外部焦点保护、快捷键修饰键交接、恢复保护、焦点失败和停止等待输入结束。Beta 4 原生测试验证了预览宿主的有界命中、不主动激活以及首击激活后按下／松开不落入游戏；该原型不验证真实应用中的完整焦点和光标映射路径。布局回归覆盖位置和大小恢复、折叠、缩小再放大，以及 16 种视口／DPI 组合。

Beta 5 路径回归还提取生产 `OverlayDrawer::MessageHandler` 和光标交接方法，覆盖真实 ImGui 工具栏按钮在绘制过程中打开编辑、两条 HWND 路由、事件位置与当前光标位置不同、继承修饰键的松开未投递到宿主、旧缩放窗口的延迟失焦／取消通知，以及预览中的映射光标交接。测试替换 Windows 焦点、捕获及坐标映射为确定性桩；它们不能证明系统前台授权或具体游戏行为。详见 [Beta 5 输入路径复核](../reviews/20260910-beta5-parameter-input-routing.md)。

## 切屏自动停用开关

主页“高级 → 切屏时自动停用生效效果组”默认关闭，配置字段 `stopEffectsOnTaskSwitch`。开关更改自动保存并立即影响下一次切屏。开启后沿用 0.6.6 的全屏范围：Alt+Tab、Win+Tab（可带 Shift）对启动中／运行中的全屏会话排队停止，挂起自动缩放并停止倒计时，等待手动重新启用。窗口效果组、空闲／停止中的状态不重复停用；系统组合键始终放行。关闭仅关闭此额外策略，源窗口销毁等原有生命周期停止仍保留。参数面板内部焦点切换不触发任务切换钩子。

Run-ParameterInputTests.ps1 同时运行生产切屏钩子、服务和运行时片段回归，覆盖开关、修饰键、全屏范围、重复事件、自动启动挂起、普通按键和设置实时变更；配置测试覆盖缺失／错误值默认关闭及双向保存重载。

| 测试组合 | 状态 | 记录内容 |
| --- | --- | --- |
| 普通窗口游戏，WGC，无补帧 | 待实测 | 参数点击是否触发游戏动作，首击返回，预览期间游戏操作 |
| 锁鼠游戏，全屏，3D 锁鼠开启 | 待实测 | 打开编辑是否释放鼠标，越界拖动，返回后重新捕获 |
| 普通游戏，GDI／DwmSharedSurface | 待实测 | 编辑失焦时的画面停顿、输入响应及预览恢复 |
| 全屏游戏，Desktop Duplication | 待实测 | 宿主与叠加层是否影响捕获，静态画面的响应 |
| FSR 补帧 | 待实测 | 首击、静态源、手动重建后的面板状态 |
| XeSS 补帧 | 待实测 | 首击、静态源、手动重建后的面板状态 |
| DLSS 补帧 | 待实测 | 独立叠加层、帧队列、失焦期间的参数响应 |

每条记录应包含游戏和版本、Windows／驱动、捕获方式、补帧方式、锁鼠设置、失焦后的暂停／降帧／后台输入表现及复现步骤。仅覆盖程序原有支持的捕获／窗口／补帧组合。

还需人工检查：参数按钮和快捷键从编辑／预览关闭、预览时按钮选中状态、停止快捷键时仍按住滑条、游戏退出、Alt+Tab／Win+Tab、跨屏移动、不同 DPI，以及重建期间切到其他应用。发现后台原始输入仍响应时，应标为该游戏未实现输入隔离，不能视为通过。
