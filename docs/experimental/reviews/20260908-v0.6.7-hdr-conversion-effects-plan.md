# 0.6.7：HDR 组件方案与实施记录

日期：2026-09-08。已接入独立「HDR 组件」主分类与三个组件，继续覆盖同一 `067 local`。旧配置中的 HDR 开关保持隐藏并关闭，仅显式转换组件按效果链启用 HDR 捕获／输出。实际界面和 NVIDIA GPU 验收由用户进行。

## 当前修改

- 配置页移除 HDR 兼容开关所在卡片，不留下空白占位。
- 新配置原本默认关闭；已有配置加载后，将默认配置和各应用配置中的 HDR 标志清除。发生变化时沿用现有保存机制写回，其他标志、效果组和参数保留；配置恢复／迁移路径也保存关闭后的值。
- `ScalingWindow::Start` 在捕获、窗口和 GPU 创建前生成颜色计划，分别决定捕获与输出；旧配置标志不能单独开启 HDR，重启重新规划。
- 复用底层转换实现，按每个节点选择颜色路径；HDR → SDR 后的 DLSSNR 使用 SDR，SDR → HDR 后按实际输入进入 HDR。
- Release x64 提交前构建已通过。实际 Magpie 界面与 GPU 运行由用户测试；未通过启动程序验证旧配置迁移。最终部署继续覆盖固定 `067 local`，以部署清单为准。

## 三个效果器的定位

以下为正式名称与 ID。效果器选择器左侧新增独立主分类「HDR 组件」，直接列出 HDR → SDR、SDR → HDR、RTX Video HDR 三项。后续组件增多时再细分子分组。使用标签检索 HDR、SDR、色调映射和兼容，RTX Video HDR 同时保留 RTX Video 家族搜索词。添加面板只选效果器，参数仍通过参数按钮和工具栏展示。

分类悬停说明：「连接 HDR 与 SDR 处理流程，用于搭建颜色转换、SDR 效果兼容和 HDR 扩展效果组。」每项的一行摘要明确转换方向，底部详情说明输入条件、输出类型和建议位置，方便用户确定它在效果组中的前后关系。

| 效果器 | 用途和建议位置 | 与其他转换的区别 |
| --- | --- | --- |
| HDR → SDR：`Color\HDR_to_SDR` | 位于需要 SDR 输入的效果之前，将 HDR 映射到它们可处理的范围 | 提供兼容配对和供 SDR 观看的显示映射两种模式 |
| SDR → HDR：`Color\SDR_to_HDR` | 位于 SDR 处理段之后，向 HDR 输出 | 有配对映射记录时按对应曲线恢复范围；原生 SDR 输入则使用白点／亮度映射，不能直接套用配对反函数 |
| RTX Video HDR：`RTXVideo\RTXVideo_HDR` | SDR 效果之后，通过 NVIDIA 算法扩展 HDR | 属于 AI 扩展，可作为普通 SDR → HDR 的替代终点；不是原始 HDR 高光的无损恢复 |

普通 SDR → HDR 内部区分「配对恢复」和「原生 SDR 映射」。可根据上游元数据选择默认模式，并在参数中明确当前模式。缺少配对记录时不得假装恢复原始 HDR。用户无须手动匹配两端白点或峰值参数。

HDR → SDR 提供兼容配对和 SDR 显示映射，包含白点、峰值、曝光与高光压缩参数。SDR → HDR 提供自动、原生 SDR 白点映射和配对恢复三种模式；本项白点／曝光仅在原生映射时使用。普通转换参数按现有受控重启应用；配对恢复时工具栏禁用本地白点／曝光，自动沿用上游值。RTX HDR 的对比度、饱和度、中间灰和峰值通过 SDK 每帧参数实时应用，后续帧携带更新后的颜色元数据。

HDR → SDR → HDR 之间经过量化、裁切或效果器处理后，无法承诺无损往返。当前配对曲线会为高光预留 SDR 码值，画面分布与普通 SDR 素材也有差异；对依赖 SDR 画面分布的 AI 模型，需要实测，而非标为通用无损兼容。

## 用户可搭建的组合

```text
HDR 源 → HDR→SDR → SDR 效果 → SDR→HDR（配对恢复）→ HDR 显示
HDR 源 → HDR→SDR（显示映射）→ SDR 效果 → SDR 显示
SDR 源 → SDR 效果 → SDR→HDR（白点／亮度映射）→ HDR 显示
SDR 源 → SDR 效果 → RTX Video HDR → HDR 显示
```

首个组件决定请求的捕获域：HDR → SDR 请求保留 HDR，SDR → HDR／RTX HDR 从 SDR 捕获开始。这不是对任意源应用原生 HDR 状态的可靠识别。HDR 捕获目前要求 Graphics Capture 和源屏幕开启 Windows HDR；HDR 输出要求各目标屏幕开启 Windows HDR。程序不自动修改系统设置。

普通 SDR → HDR 和 RTX Video HDR 都消费 SDR，不应默认串联两个扩展步骤。组合不满足输入条件时，在启动前说明具体修改方法，例如：「RTX Video HDR 需要 SDR 输入。请移除前面的 SDR → HDR，或用 RTX Video HDR 替换它。」

实际补帧阶段位于图像效果链之后。说明和校验按执行阶段处理，不能让用户误以为拖动补帧条目即可改变 HDR 转换与补帧的先后。

## 源码基础与管线实施

已有 [`HdrSurfaceAdapter`](../../../src/Magpie.Core/HdrSurfaceAdapter.h) 提供 HDR／SDR、scRGB 和 HDR10 的 GPU 转换。其 [`HdrColorTransform`](../../../src/Magpie.Core/HdrColorTransform.cpp) 使用峰值归一化的对数压缩和配对反函数；代码也明确它不是显示色调映射。直接将普通 SDR 白色输入该反函数，可能被扩展到峰值，因此不能仅把现有函数包装成通用 SDR → HDR 效果。

当前实现让颜色状态沿每个效果的输入／输出边界传递，捕获状态与输出状态已拆开：

1. 在创建窗口和 GPU 资源前规划整条链，记录传递函数、色域、范围、白点／峰值、纹理格式和透明度规则；配对转换另携带映射参数与配对标识。
2. 捕获格式由组件指定的保留需求决定，输出格式／颜色空间由效果链终点决定。显式 HDR 链按规划结果启用，不依赖旧配置开关。
3. 内部 HDR 统一采用线性 scRGB 约定，`1.0 = 80 nit`。源和输出边界负责必要的传递函数、色域及亮度单位换算。Windows Advanced Color 的 scRGB／FP16 约定见 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/direct3darticles/high-dynamic-range)。
4. SDR 段明确传递函数和白点；当前显式 HDR → SDR 输出 RGBA8，SDR → HDR 输出 FP16，量化损失需要纳入画质比较。
5. DLSSNR 等后端依据当前节点输入选择路径，避免将整条 HDR 链里的 SDR 段再次当成 HDR 包装，或重复乘除白点。
6. 会话启动和受控重启时重新规划配对关系，按当前纹理尺寸绑定上下游资源；`HdrFrame` 的帧号、捕获序号、资源代际、时间戳和生成帧标识保持贯通。运行中切换 Windows HDR 或跨屏后的状态变化仍需验收，本轮未增加显示状态变化监听。
7. HDR 输出前核对显示器能力、Windows HDR 状态及捕获／呈现路径。条件不满足时提供「开启目标屏幕 HDR」或「将效果组终点改为 SDR」等操作，不自动修改系统显示设置。
8. 改变颜色域或纹理格式的参数触发受控重建；只影响数值且后端支持的参数才实时更新。DLSS FG、XeSS FG 和不同呈现后端分别验证颜色、帧序和资源生命周期。

原画对比也按捕获／输出组合映射到正确颜色域。截图导出不使用 RTX 标记着色器覆盖已经生成的 HDR 图像。转换或 RTX 绘制失败时通过当前会话调度器提示并停止缩放；SDK 异常要求完整重启，并保留故障模块直到进程结束。

## RTX Video HDR 的依赖边界

NVIDIA 官方 RTX Video SDK 提供 SDR → HDR 能力，并列出 Windows、DX11／DX12／Vulkan／CUDA 及 RTX 20 系起的硬件支持；当前官方页面列出 SDK v1.1。详见 [SDK 入门页](https://developer.nvidia.com/rtx-video-sdk/getting-started) 和 [NVIDIA 技术介绍](https://developer.nvidia.com/blog/enhancing-low-resolution-sdr-video-with-the-nvidia-rtx-video-sdk/)。

本机原有 `RTXVideoDenoiser.cpp` 调用 Maxine Video Effects SDK 的 `VideoSuperRes`。新增 HDR 使用独立 `RTXVideoHdr` 后端与 `Magpie.RtxVideo.dll`，通过三个自定义 C ABI 入口调用官方 SDK；既有 VSR／DLSS 运行库沿用原来源。`EffectProtocolCatalogC.h` 不再把此显式转换加入旧的 HDR 输入／HDR 输出自动适配器路线。

SDK 已从官方公开 [NVIDIA NGC DLPP 1.5 文件目录](https://catalog.ngc.nvidia.com/orgs/nvidia/multimedia/models/dlpp/1.5/file-browser) 取得。`scripts/Fetch-RtxVideoSdk.ps1` 固定校验 `RTX_Video_SDK_v1.1.0.zip` 的 SHA256：`ABF4F34E2B5A618E355B0D5A0365D8ECC3DB4396E756E4C850A867E1AE2ED69E`。官方 D3D11 示例与编程指南确认 RGBA8 SDR 输入、FP16 线性 scRGB 输出；运行库 Authenticode 签名有效，签署者为 NVIDIA Corporation。

桥接 DLL 独立链接 RTX Video SDK 的 NGX 静态库，主程序继续使用已有 DLSS SDK。SDK 静态库自身仍导出 NGX 符号；主程序只调用自定义 ABI，不链接桥接导入库。此隔离解决构建时 SDK 混用，实际驱动下的 SDK 组合仍需 GPU 验收。运行包增加桥接 DLL、`nvngx_truehdr.dll` 和完整 `NVIDIA-RTX-VIDEO-LICENSE.pdf`；SDK／第三方二进制不进入 Git，公开发布沿用项目已有审核流程。
