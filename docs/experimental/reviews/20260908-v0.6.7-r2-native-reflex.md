# 067 r2：DLSS FG 原生 Reflex 接入

日期：2026-09-08。改动基线：`618efceba22a17ab78e74f250c84d89d32f4f004`，本地 `0.6.7` 分支。按维护者要求将 DLSS FG 与 Reflex 连接，继续覆盖固定 `067 local`。

## 结果与边界

实现直接 NGX + 原生 NVAPI 的低延迟接入：DXGI 路径默认请求 Reflex On，Boost 关闭，额外帧率上限为 0。Sleep、工作帧标记、FG 队列登记、异步呈现标记已接入实际执行位置。软件逻辑测试通过；实际 NVIDIA 驱动、视觉效果、延迟收益和官方验证工具检查由用户验收。

这与 XeSS FG 连接 XeLL 的目的相同，接口形式不同：XeSS 的 SDK 直接接受 XeLL context；当前 NGX FG 没有对应的 Reflex context 参数，应用负责接入驱动低延迟接口并维护工作帧与呈现 ID。此改动没有更换 NGX 或呈现后端。

Magpie 只能标记自己的捕获和处理周期。没有源游戏的输入、simulation、camera 构造信息，因此没有伪造 `INPUT_SAMPLE` 或把日志描述为源游戏点击到显示的完整延迟。产品目录也没有增加“官方认证”或已验证延迟收益的宣传。

## 前后差异

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 低延迟等待 | 只有现有捕获限帧、FG 输入门和呈现容量控制 | 增加每个基础工作帧一次 NVAPI Sleep，在捕获 Update 前调用 |
| 普通工作阶段 | 没有 Reflex 标记 | Sleep → Simulation Start/End → Render Submit Start；效果链完成、FG 可能发布第一张插帧前 End |
| FG 队列 | 独立 D3D12 DIRECT 队列，未向 Reflex 登记 | 登记为带外渲染队列，实际 ExecuteCommandLists 两侧发送异步标记 |
| 帧身份 | 捕获 ID 和 generated 布尔值 | NGX BackbufferFrameID、guidance 与 Reflex 使用同一基础 ID；每张候选输出另有递增 present ID |
| 共享槽/FIFO | 没有 Reflex 身份 | 基础 ID、present ID 与颜色在同一槽锁内发布和复制；前端不读取正在变动的后台当前帧 ID |
| SDR 发布身份 | 共用元数据的基础 ID 与 generated 只在 HDR 分支填写 | 所有颜色模式统一填写帧身份，SDR 插帧也能正确选择带外呈现标记；颜色转换保持原分支 |
| 实际呈现 | 没有 Reflex 呈现标记 | 前端附加绘制使用带外渲染标记；实际 DXGI Present 两侧，真实帧使用普通呈现类型，插帧使用带外呈现类型 |
| 重试与静止画面 | 没有 Reflex 生命周期 | 重复/等待捕获保留候选周期；FG 暂存与呈现重试不重复 Sleep；纯 UI 重绘不冒充新基础帧 |
| 设备线程约束 | 前端 D3D11 使用 SINGLETHREADED | 仅 DLSS FG 的前端设备不设置该标志，以允许捕获线程调用同一呈现设备的 NVAPI；立即上下文仍只由前端使用 |
| 失败与退出 | 无 Reflex 状态需要清理 | 查询/调用失败停止 Reflex 并恢复 Off，保留画面；错误记录操作、状态码及下一步；停止缩放后在线程退出前停用，驱动对象在线程 join 后释放 |

## 设备、线程与资源

- `ReflexController` 在 Renderer 创建后台线程前完成初始化。所有 CPU 基础标记和 Sleep 都针对真正拥有 DXGI 交换链的 D3D11 前端设备；D3D11 异步呈现标记也使用它。
- 后台在现有限帧和消息处理之后、`FrameSource::Update()` 之前 Sleep，此时尚未申请本帧共享发布槽。只有新基础周期调用一次；一个候选捕获尚未产生新图像时，不按轮询次数重复调用。
- NR、光流和普通效果仍在各自现有设备/队列执行，处于 Magpie 的普通工作区间。FG 自己的 D3D12 队列登记为带外渲染，生成工作和前端呈现通过基础 ID、present ID 对应。
- 登记 FG 队列前核对 D3D12 与呈现设备的 adapter LUID。跨显卡组合回退，日志提示选择相同 NVIDIA 适配器后重新启用缩放；不把不同显卡的成本假定为同一个 Reflex 时间域。
- 现有 fence、keyed mutex、输出完成标志、共享槽和 FIFO 保持其所有权规则。没有增加 GPU readback、额外 GPU fence 或扩大在途帧数量。
- Sleep 不持有控制器的配置互斥锁，避免后台等待时挡住前端 Present 或 Stop。失败只请求一次停用，句柄和函数指针在两个线程结束前保持有效。
- 尺寸变化/DirectComposition 过渡暂停低延迟睡眠，回到 DXGI 时按状态切换恢复；永久使用 DirectComposition 的配置不初始化 Reflex。取消的候选周期允许留下 ID 空档，后续基础 ID 不倒退，也不重复使用。

## 开销与尚未接入的部分

新增的是功能所需的 NVAPI 调用。正常基础帧有 1 次 Sleep、4 个普通阶段标记；每次生成提交有 2 个 D3D12 标记，每次带内容的 DXGI 呈现有 4 个前端渲染/呈现标记。它们不是零开销；驱动有意推迟下一周期的起点，以尝试减少排队延迟。

`SetSleepMode`/`GetSleepStatus` 只在模式切换时调用，接口解析/模块加载只在初始化发生。稳定帧不新增文件日志、CPU 分项计时、GPU 时间查询或 `GetLatency` 轮询；此前关闭的详细计时仍默认关闭。

现有捕获限帧、Front Edge Sync 的输入门、FIFO 呈现节奏和 DXGI 容量门继续工作。Reflex `minimumIntervalUs=0`，避免再配置一份相同 FPS 上限；是否存在驱动等待与应用门控的实际叠加成本仍需 A/B 验收，不能仅凭设置为 0 就宣称吞吐量一定不受影响。

仍待后续工作：

- 默认 On 的 NVIDIA 驱动兼容性、队列标记和真实显示间隔验证，尤其是本项目 D3D11/D3D12 多设备组合。
- 可供用户 A/B 的 Off/On/On+Boost 选项。本轮没有新增参数 UI，Off 用于不可用、失败、暂停和退出回退，未启用 Boost。
- 诊断专用延迟查询、PCL/Reflex 验证工具、显示端采样；不在普通运行路径持续查询。
- `SetReflexSync` 的显式 vblank、队列时间反馈及与自管节奏的整合。公开字段不足以证明当前路径的最佳值，本轮没有填入猜测数据，也没有使用 Reserved 接口。
- 完整 Streamline DLSS-G + sl.reflex/PCL 迁移仍是单独的 R2-10 决策，未纳入本轮。

## 自动检查与用户验收

`tests/Run-ReflexControllerTests.ps1` 直接测试生产 `ReflexController.h`，替换驱动边界，不运行 Magpie 或加载 NVIDIA 驱动。覆盖：

- 2x/3x/4x、50 次候选捕获重试、无效插帧跳过、输出 ID 单调性。
- 后台推进到下一帧时，前端仍使用先前发布的基础 ID 与 present ID。
- 纯 UI 不产生伪基础帧；暂停恢复、取消候选后的 ID、配置只在状态变化时更新。
- 13 个驱动失败位置、一次停用/错误记录、失败后停止重复调用。
- Sleep 与前端 Present/Stop 并发，Sleep 不占用阻止退出的互斥锁。

Release x64 构建核对官方头文件 ABI 与所有真实调用位置。软件检查不证明驱动已经执行低延迟优化，也不证明显示端延迟下降。

原有 NR/FG 软件资源回归也通过：25 组残差输出对照、96 次 FG readback，详细计时关闭/开启两种编译均通过。最终发布仍使用关闭详细计时的配置。

用户验收建议保持同一源应用、分辨率、光流档位、HDR/刷新率/VRR 设置：

1. 从窗口化源开始，先用 FG 2x，确认正常显示、工具栏参数编辑、停止和重新启用。
2. 检查日志的 `DLSSFG Reflex: native low latency On`；若出现 `unavailable`，按该行的操作/状态与后续步骤定位。
3. 测试 NR+FG、设备支持的 3x/4x、静止后恢复运动、窗口大小变化和 HDR。
4. 对照之前 `618efceb` 的采样记录观察基础帧率、实际显示间隔、操作延迟及稳定性；没有同条件采样时先报告体验，不填写未经测量的收益百分比。

## 依赖与构建

官方 NVAPI 固定版本：`NVIDIA/nvapi@87dca625e83fd89a983e19b904e5f3a580da90d2`。运行 `scripts/Fetch-NvapiHeaders.ps1` 获取并验证 9 个头文件的 SHA256，放在工作区 `dependencies/nvapi-sdk`；非标准路径使用 `NvapiSdkDir` 覆盖。缺依赖时编译前给出该修复入口。

使用官方函数声明、结构版本宏和 `nvapi_interface_table`；不手工推测 ABI 或硬编码未公开入口。只从 System32 加载系统 NVIDIA `nvapi64.dll`，不向运行包分发驱动 DLL。包内附带 NVAPI MIT 声明，并纳入部署校验清单。
