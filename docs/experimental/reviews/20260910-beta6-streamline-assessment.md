# Beta 6：Streamline 接入评估

评估日期：2026-09-10。范围：现有直接 NGX DLSSFG 与原生 NVAPI Reflex 路径。结论是先完成现有路径的状态、调度和计时修复，Streamline 作为独立迁移项目，不在 Beta 6 中直接替换。

## 官方约束

完整 SL DLSS-G 需要配套 SL Reflex、匹配的帧身份及资源标签。插件会接管呈现，窗口模式和尺寸变化需要专门处理。等待对象必须只有一个使用方：推荐由 SL 管理时，应用不请求对应标志，也不调用获取等待对象和设置最大帧延迟；若应用请求该标志，则应用承担管理职责。这些约束适用于加载 `sl.dlss_g` 的交换链，不能套用于当前直接 NGX 路径。[NVIDIA DLSS-G 指南](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideDLSS_G.md)

SL Reflex 的能力查询、选项、Sleep、PCL 标记共同组成接入；Off 状态也有 Sleep／标记要求。因此迁移不能止于替换一个 Sleep 函数。[NVIDIA Reflex 指南](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideReflex.md)

## 针对本仓库的成本判断

以下是根据当前源码作出的工程判断，不是 NVIDIA 对 Magpie 的兼容性承诺。

| 范围 | 当前实现 | 迁移所需工作与主要风险 |
| --- | --- | --- |
| 设备和交换链 | D3D11 捕获／效果／呈现，DLSSFG 使用共享 D3D12 设备和队列；`AdaptivePresenter` 可切换 DXGI／DComp | 初始化顺序、SL 代理交换链、设备身份及跨 API 路径都需原型验证；无法把当前 D3D11 呈现器视作已满足指南中的 D3D12 接入 |
| 颜色与引导资源 | `FrameGuidanceService` 提供估计运动和深度，D3D11／D3D12 互操作；共享纹理由 fence 保护 | 将颜色、运动、深度和生命周期映射为标签，逐项验证资源状态、尺寸、有效区和同步；已有光流不等于游戏引擎提供的运动和深度 |
| 帧身份 | `_capturedFrameId`、捕获序列、资源代次和独立 Present ID；生成帧先于真实帧入有界环 | 给同一基础输入分配 SL token，关联常量、标签、Present 标记；捕获等待不得反复分配有效帧，重建和中断必须清除旧资源关联 |
| HDR | canonical FP16、PQ 转换和颜色元数据分层传递 | 对照 SDR、FP16、HDR10 的标签、交换链颜色空间和 UI 合成结果；不能只确认初始化成功 |
| 叠加层 | 参数面板、光标、原图对比与处理后图像在前端合成 | Magpie 自己的 UI 可以分离，源应用已经画入捕获画面的 HUD 无法据此恢复成真正无 HUD 场景；需要验证插帧、编辑、对比和截图各自取图时刻 |
| 窗口重建 | 参数焦点宿主、源窗口重定位、DXGI／DComp 切换和延迟参数重启 | 建立 SL 关闭插帧、等待正在使用的资源、重建、重新标记和恢复的完整次序；必须保留外层循环处理输入和取消的能力 |
| 统计与回退 | 应用管理输出 FIFO、槽位和 Present 计数 | SL 路径单独定义真实帧、生成帧、实际呈现数量和间隔；不可把当前 FIFO 计数直接当成 SL 显示结果。加载失败时需要完整回到现有呈现器 |

工作量判断为跨设备、资源和呈现生命周期的架构迁移，不能作为 Beta 6 的局部驱动修复。当前没有运行 SL 原型，因此没有可靠的工期、性能收益或特定硬件兼容性结论。

## 若后续采用 SL 托管呈现

为 SL 创建独立 Presenter，明确由 SL 持有等待对象和最大帧延迟控制；该路径停用应用的 `FrameLatencyGate` 和对同一交换链的容量等待。普通 DXGI Presenter 继续拥有自己的等待对象。避免用运行时非空句柄推断所有权，也避免两套路径共用一个可变的容量状态。

先做单一 NVIDIA 适配器、SDR、单一窗口、2× 的最小原型，再扩展跨 API 共享、HDR、3×／4×、叠加层、输入焦点和重建。通过真实显示间隔及延迟比较后，才决定是否替换当前实现。

## 现有 NGX 路径的资源池评估

Beta 6 保留生成帧输出、共用 allocator、SDK 插值禁用标志读取及发布复制的 fence 等待。已加入按插值索引的生成 fence CPU 等待统计（验证构建开关），保留发布事务／复制 fence 的低频统计，并增加有界 FrameTrace 事件。它们测量 CPU 墙钟时间，不能当作 GPU 执行时间。

后续资源池原型至少应为每个在途上下文独立持有 allocator、命令列表、生成输出、插值状态缓冲和对应 fence 值；颜色、引导数据及 NGX 功能对象的并发约束仍需验证。只有实际测量显示这些等待为主要瓶颈，且资源生命周期验证通过，才扩大在途数量。当前没有实机数据支持删除等待或增加并行度。
