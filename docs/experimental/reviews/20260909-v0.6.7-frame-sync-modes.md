# 067：帧同步模式与 Reflex 职责

日期：2026-09-09。基线 `3928bdbe112c93b07d9d75ec224176582e9e2fc7`，继续使用本地 `0.6.7` 分支和固定 `067 local` 目录。

## 行为变化

新增 Async 和普通效果的 NVIDIA Reflex 驱动限帧。保留旧开关、目标与 Front Edge 默认；模式字段 `frameSyncMode` 为 0 Front Edge、1 Async、2 Reflex，未知值回到 Front Edge。主页和工具栏共用开关／FPS／模式的字段合并与受控重启机制，运行中不会提前应用未重启的模式。

| 情况 | 之前 | 当前 |
| --- | --- | --- |
| 普通效果开启帧同步 | 只有提交前的 Front Edge | 可选择 Front Edge、严格 Async 或 Reflex |
| Async 迟到 | 原普通计时器对齐旧网格，下一间隔可能缩短 | 按实际捕获开始计时，迟到不补赶；最后不足 1 ms 使用可中断定时器 |
| 普通 NR／SR 的 Reflex | 未接入 | 沿用同一个控制器，取帧前 Sleep，统一基础 FPS 交给驱动 |
| Reflex 失败 | 只有 FG 低延迟回退 | 普通路径回退同目标 Async，显示下一步；临时窗口调整与永久失败区分 |
| DLSS FG | Reflex On、Boost Off、驱动上限 0 | 保留此设置；Async 可控制基础输入，Reflex 限帧选择暂沿用 Front Edge 并说明 |
| XeSS FG | XeLL 低延迟与目标设置 | 保留；任何模式选择均显示 XeLL 实际接管 |
| FrameRate Filter | “基于 Front Edge Sync” | “跟随帧同步目标”，旧 ID／自定义值保留 |

## 调度与生命周期

- 共享结果消费反馈从 Front Edge 的具体等待位置中分离。新模式沿用单个尚未消费结果的控制，不因为换等待位置而丢失背压；DLSS 的 FIFO、槽锁、fence、生成帧／真实帧顺序保留。
- Front Edge 保留现有消费者时钟；Async 在 StepTimer 内控制基础间隔；Reflex 接管时 StepTimer 不再添加相同的基础上限。更低的应用／捕获上限先合并，再生成唯一目标。
- 原生 Reflex 接口配置改为低延迟、Boost、目标的明确结构。相同目标不重复配置；呈现暂停清除驱动设置，恢复时应用最近的目标，失败时清除后回退。每个候选处理周期只 Sleep 一次；等待捕获／重复捕获保留周期，UI 重绘不伪造新的基础帧。
- 普通 Reflex 的前端设备允许跨线程调用；初始化后台设备后核对两端 adapter LUID。跨显卡组合回退 Async。多设备 GPU 时间关联和真实延迟仍待实测。
- DLSS FG 继续使用零驱动上限。选择 Async 不暂存已经处理完的输入等待 Front Edge 时钟；FG 逐张输出的节奏保持原有实现。选择 Reflex 暂保留 Front Edge，避免未经验证就更改驱动对 FG 倍率的解释。
- `bUseMarkersToOptimize` 保持关闭，仍发送标准阶段标记；原生指南将额外 CPU 标记优化与 Boost 关联，本轮未开启未经验证的 Boost 优化。
- 配置恢复现在接受原有合法的 0 自动和 1–1000 FPS，修复新模式的非法值时保留其他字段。恢复缓存策略升为 v2，避免复用按旧范围生成的修复结果；健康配置不会因为增加模式就触发重置。

## 待用户验收

- 普通 NR／SR 的三种模式在相同目标下的实际帧间隔、捕获后延迟、CPU／GPU 占用。
- Reflex 对不同驱动、同显卡多设备、HDR、原画对比和仅 UI 重绘的影响。
- DLSS 2x／3x／4x 的 Front Edge／Async，静止恢复、窗口调整、停止／重新启用；XeSS FG 的 XeLL 接管。
- 新设置的主页／工具栏同步、保存和重启，以及自动目标、小数与较低上限。

DLSS FG 的 Reflex 驱动限帧和 Reflex Sync 高级反馈仍未实现，不作为本轮已完成内容。软件测试不证明实际延迟收益。
