# Beta 4：旧帧消费完成与皮肤结构强度

## 问题与行为

`Renderer::_UpdateFrontendBase` 在序列或资源代数不匹配时释放共享纹理，但没有推进同步消费确认。先前稳定画面已经呈现时，后续重绘的 `contentFrame=false`，不能解除后端等待。

本次让成功丢弃在现有槽互斥保护下推进确认并唤醒消费者等待；释放失败仍为重试，不虚报丢弃。`Ready/Retry/Dropped` 区分基帧结果，记住被丢弃的槽编号，重复通知和强制重绘不会再次释放或重放旧基帧。新发布编号可正常消费，重建共享资源时清空丢弃记录。

DLSS 的环形队列收到丢弃结果后完成当前 FIFO 任务并释放相应槽，不更新呈现统计或呈现时钟。普通共享槽与 XeSS 的同步确认只在使用该协议时更新。

DLSSNR `skinStructureStrength` 的着色器参数元数据、设置结构默认值与运行时解析边界统一为默认 0、范围 0–2；保存参数名和 0.05 步长不变。旧负值由正常参数归一化和后端防御性 clamp 处理。

## 验证

`tests/Run-FrontendDropTests.ps1` 从生产代码提取拒收路径、前端结果分派、后端等待条件、DLSS 丢弃完成分支以及 NR 设置解析。使用可控 GPU 调用替身，MSVC C++20 `/W4 /WX` 编译并执行通过。

- 捕获序列变化和资源代数变化，分别覆盖已有/没有有效基帧。
- 成功丢弃后后端解除等待，清除待呈现状态；重复通知 1000 次不会重新释放或呈现。
- 后续新编号可继续通过消费入口。
- 获取失败和释放失败不推进确认，保持重试；释放恢复后可完成丢弃。
- 关闭同步不写单槽确认；DLSS 丢弃完成 FIFO、归还正确槽，失败重试不提前完成。
- NR 默认、旧负值、区间内值、上限溢出及 NaN；参数元数据同步检查。

该测试隔离同步协议，不加载 SDK，也不替代 GPU 和游戏切屏测试。用户 `magpie (30).log` 没有旧帧拒收且持续处理新帧，本修复不宣称已经解决该用户未复现的第二次开启卡顿根因。
