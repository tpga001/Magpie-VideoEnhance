## 确认存在的代码缺口

### 1. 参数焦点已被允许，但源窗口状态变化仍触发全屏退出路径

`ParameterInputHost::_BeginParameterInput` 激活原生输入宿主。`SrcTracker::UpdateState` 已将这个宿主视为会话内部焦点，`_CheckForegroundFor3DGameMode` 也有对应放行；不能仅凭发生焦点切换就断言白名单遗漏。

但 `_UpdateSrcState` 仍会在源窗口不可见／最小化、尺寸变化，或全屏时位置变化的情况下请求停用／重建。焦点交接若伴随源程序的上述行为，会进入这个路径。无界面测试确认：源窗口状态不变时，单独交给参数宿主的焦点不会终止全屏；源窗口移动一像素则请求全屏重建，同样移动在窗口缩放中被接受。

**尚未确定：**第一次点击后实际改变的是源窗口位置、尺寸、可见性，还是另一个返回失败的条件。现有日志只记录统一文字，且首条触发证据被日志风暴覆盖，不能进一步断言具体值。

### 2. 等待参数输入结束时，停用／重建请求没有统一的待处理状态

`_PrepareFrontendRender` 每次失败都记录日志并调用 `_DelayedStop`，没有去重。`_DelayedStop` 的重建分支遇到 `HasHeldParameterInput()` 就直接返回，没有保存稍后必须执行的重建请求。

持续的源尺寸变化配合未结束的参数点击，会不断重复“准备失败 → 请求重建 → 输入未释放，返回”。测试中 1000 次准备调用产生 1000 条状态日志及 1000 次回调，没有呈现进展；松开后才允许销毁。这个结果与实际日志风暴一致，但测试并未模拟导致源状态变化的真实 Windows／游戏行为。

### 3. DLSSFG 队列在真正开始销毁之前被清空

`ScalingWindow::RenderNextDLSSFGFrame` 在 `_PrepareFrontendRender` 返回 false 后立即清空 `_dlssFgFrameJobs`。这些帧因此没有经过 `Renderer::RenderDLSSFGFrame` 的完成／丢弃处理，待呈现计数和槽位完成信号不会由这一清空操作回收。

若随后重建回调因输入未释放而返回，而源窗口短暂位置变化又已被 `SrcTracker` 记住，下一次检查可能恢复正常。这时没有持久的重建请求，也没有清掉的 FIFO 作业。Renderer 仍可能认为有 FG 内容待呈现：`HasPendingContent` 返回真，`RenderOverlay` 又等待这些内容完成；生产者最终还可能等待未归还的槽位。

无界面测试已复现这一组合：暂时源移动 → FIFO 清空 → 输入按住导致重建返回 → 松开后源状态正常 → 没有重建且被清掉的任务未完成消费。这是能造成持续画面／参数响应停滞的具体缺口。

## 本次验证

测试脚本保存在工作区 `.tools/067-beta5/fullscreen-parameter-crash/trace_source_state.py`，提取并执行当前生产实现的：

- `SrcTracker::UpdateState`；
- `ScalingWindow::_UpdateSrcState`、`_PrepareFrontendRender`、`_DelayedStop`、`RenderNextDLSSFGFrame`。

Win32、渲染器和调度器外围为确定性桩，验证非 3D 分支的内部焦点、源位置／尺寸／最小化、未释放输入、重复停用和 FIFO 生命周期。未创建窗口，未操作鼠标、键盘、焦点或游戏。源码路径与循环缺陷可复现；不将其等同于已复现用户点击导致源状态改变的完整实机过程。

原始日志快照及结果保存在同一目录：`magpie.log`、`magpie.1.log`、`source-state-results.log`。本次只增加文档和诊断测试文件，未修改运行代码、配置或部署包。

## 后续修复方向

1. 首次状态失败记录明确原因、真实前台 HWND、参数宿主及其交接阶段、源窗口前后矩形、可见性／最小化状态；同一事件只记录一次。
2. 使用持久的停止／重建请求，在外层循环处理。等待输入释放期间继续服务输入，不重复入队、不丢掉重建意图。
3. 统一 FG 生产取消、FIFO 丢弃完成、槽位归还及重建的顺序。只有确实进入销毁／重建时才清理队列，或者显式对每个丢弃任务完成回收；避免留下“计数非零但作业已消失”的状态。
4. 协调参数宿主焦点交接与全屏源状态检查；对可恢复的交接变化先稳定／重新检查，源程序真正关闭等不可恢复事件仍正常结束。
5. 扩大输入回归到全屏生命周期组合。此前的参数宿主／ImGui 输入测试没有执行 `_UpdateSrcState + _DelayedStop + DLSS FIFO` 这一整段，这是验证覆盖缺口。
