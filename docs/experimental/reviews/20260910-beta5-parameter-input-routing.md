# Beta 5 参数面板输入路径复核

用户报告：按钮打开后处于编辑，但点击面板外不能返回预览；快捷键打开后停在预览，点击面板不能进入编辑。本次按代码路径和无界面回归检查修复。用户要求未经同意不使用 Computer Use，因此本次验证不启动或操作应用、游戏及原生测试窗口。

## 定位结果与修改

1. **窗口消息路由不同。** 原来的状态切换只在参数输入宿主的 WndProc 中执行；实际缩放窗口经 `Renderer::MessageHandler` 到 `OverlayDrawer::MessageHandler` 时直接投递 ImGui，漏掉预览激活和面板外返回判断。现在两条路径调用同一处理方法，保留系统按键的默认处理，并忽略成功交接焦点后旧缩放窗口的延迟失焦／取消通知。
2. **继承按键可能永远等不到松开。** 打开编辑时将已按住的 Alt、Shift 等记成宿主接收过的按下，但松开可能已经投递到原窗口。现在单独记录继承状态，并依据物理松开补齐 ImGui 状态；宿主实际接收的按下仍要求完整配对。面板外返回因此不会被已松开的继承修饰键永久挡住。
3. **点击位置随处理时机变化。** 旧判断读取当前光标，预览激活还会移动宿主和解除坐标映射。现在在处理鼠标消息时立即保存 `GetMessagePos` 的屏幕坐标，用同一个位置完成区域判断和控件按下投递。
4. **参数热键抢先截断系统入口。** 原低级键盘钩子吞掉已经注册的参数热键，再异步调用操作；系统 `WM_HOTKEY` 路径未获执行。现在参数热键单独放行至系统注册入口，保留防重复和原有快捷键设置。Windows 前台激活仍需满足系统约束，代码继续检查实际前台窗口并记录激活失败；静态测试不能证明任意游戏中都会获得授权。
5. **预览命中未参与捕获交接，3D 分支提前返回。** 只读 ImGui 窗口不请求鼠标输入；即使增加悬停标记，原 3D 锁鼠仍先返回。现在按最后成功呈现的面板范围检查显示坐标，在普通捕获及 3D 锁鼠之前解除 Magpie 映射，恢复原生光标以接收点击。离开预览范围或外部应用前台时不接管光标。

预期操作保持一致：按钮或参数快捷键在关闭时进入编辑，在编辑／预览时关闭；编辑时单击面板外，在完整松开后进入预览；预览时单击控件，进入编辑并直接操作该控件；Esc 先结束弹出菜单或数值输入，再按编辑、预览、关闭逐级退出。

## 验证及边界

- `tests/Run-ParameterInputTests.ps1`：提取生产状态机、实际窗口消息入口、ImGui 输入和光标交接方法，使用真实 Dear ImGui 和确定性 Win32 桩。覆盖真实工具栏 Button、两条 HWND 入口、首击滑条／开关／下拉菜单、消息坐标延迟、继承修饰键松开、延迟失焦／取消、映射光标进入／离开预览、Esc、拖动、重建及停止。布局覆盖 16 种视口／DPI 组合。
- 反向测试逐项恢复旧的分离路由、继承键记录、当前坐标读取和缺失预览捕获交接，要求相应断言失败，防止只写会跟随错误实现一起通过的检查。
- 生产编译检查与完整 Release x64 构建检查实际头文件、SDK、依赖及链接；发布核对清单、资源、ZIP、效果和用户配置。
- 未进行本次原生输入原型、Computer Use 或实机游戏验收。Win32 桩不模拟操作系统的前台授权判定，映射桩也不能替代真实锁鼠游戏的行为。保留简短状态日志便于后续区分“未获激活”“已进入编辑”和“已完成返回预览”。

## Windows 依据

- [SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)：前台切换受系统约束；获得最后输入是允许条件之一，满足条件仍可能被拒绝。
- [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)：系统向注册窗口投递 `WM_HOTKEY`，`MOD_NOREPEAT` 抑制自动重复通知。
- [GetMessagePos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessagepos)：返回最近检索消息的光标屏幕坐标，需要按有符号坐标解包。
