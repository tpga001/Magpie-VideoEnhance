## 1. NR 与 FG 的源码开销结论

| 路径 | 核对结果 | 本轮处理 |
| --- | --- | --- |
| NR 普通输入/输出 | 共享输入复制或 BGRA 转换，D3D11/12 依赖，Evaluate 后复制到效果输出 | 保留。输出、输入共享直通需要新的资源寿命合同 |
| NR 缩小输入 | 两次颜色降采样、一次 guidance 重采样，再执行模型 | 保留采样算法和输入设置 |
| NR 残差 | 低分辨率残差控制、可选水平放大、垂直合成；随后整帧复制 | **合成直接写兼容效果输出，减少最后一次 CopyResource 和中间输出纹理** |
| NR 命令提交 | 已有四个命令槽、同帧及输入/参数修订去重 | 保留。没有把它误判为每帧 CPU 等 Evaluate |
| NR 详细计时 | 原来一直创建 timestamp heap/readback，发出查询并采集，CPU 每帧读取多个时间点 | **改成默认关闭的验证构建选项** |
| NVOF 详细计时 | 原来一直创建四组 D3D11 查询并提交/轮询 | **随同一验证选项默认关闭**，光流与置信度计算本身不变 |
| FG 等待事件 | fence 未完成时，每次等待都创建/销毁事件 | **每个 FG 实例创建一次并复用**；保留等待和超时 |
| FG 禁用插帧标志 | 每张生成帧 Map/Unmap readback，检查首字节 | **初始化时映射、释放时解除映射**；读取前仍检查 GPU 完成 |
| FG Evaluate / 发布 | 每张插帧仍执行 Evaluate 完成等待、颜色复制及发布完成等待 | 保留。这些等待当前保护单 allocator 和单输出纹理，不直接删除 |
| 光流共享 | 同帧生产一次、按会话选择共享提供器，目标尺寸缓存 | 保留。按需 confidence / 更广的资源池复用继续验证 |

可以确定的减少量：

- 兼容的 SDR NR 残差路径：每次合成少一次整帧复制、少一张 `RGBA8` 全尺寸中间输出纹理。纹理逻辑大小为 `宽 × 高 × 4` 字节；实际显存分配和帧率收益仍取决于驱动及其他瓶颈。
- FG：每张插帧少一次 Map 和一次 Unmap；需要 CPU 等待时，事件创建/关闭从每次等待变为每个实例生命周期一次。
- 默认验证选项关闭时，NR/NVOF 不创建和提交上述专用 GPU 计时查询；NR 对这些项目的 CPU 读时钟和统计也被关闭。FG 的 120 帧详细汇总关闭。

本轮不声称全部日志已去掉。首次成功、初始化、错误、引导状态变化继续记录；Renderer 原有呈现/发布统计仍存在，不属于本次全面清理对象。

## 2. 输出与同步保护

### NR 直接合成

`CreateCompositeOutput()` 在初始化阶段尝试创建效果输出 UAV，仅在输入输出是不同纹理且输出支持 UAV 时复用。其余情况保留独立中间纹理和最后复制。Draw 中若输出对象变化，也保留复制交接。

着色器、残差参数、正负残差/HSL 顺序、alpha 和原始颜色读取方式都未改。FP16 HDR 路径本来不执行这套 SDR 残差重建，本轮保持该边界。

代码：[创建目标](../../../src/Magpie.Core/DLSSNRFilter.cpp#L1143)、[残差合成](../../../src/Magpie.Core/DLSSNRFilter.cpp#L1683)。

### FG 映射与事件

readback 内存保持映射符合 D3D12 的映射用法，但 Map 不代替同步；必须在 GPU 写入完成后读取。[Microsoft Map 文档](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12resource-map)

仍复制并读取 SDK 的禁用插帧标志，不能把它当作可删除的性能统计。事件复用后，唤醒本身不足以证明当前 fence 已完成，因此再次验证完成值；`UINT64_MAX` 的设备移除返回值按失败处理，不被当作所有任务完成。

代码：[等待](../../../src/Magpie.Core/DLSSFrameGenerator.cpp#L152)、[持久映射](../../../src/Magpie.Core/DLSSFrameGenerator.cpp#L305)、[读取首字节](../../../src/Magpie.Core/DLSSFrameGenerator.cpp#L353)。

### 同尺寸 guidance 快速路径暂缓

尝试验证 NR 100% 输入时跳过 guidance pass，软件设备测试发现原 pass 与直接复用并非所有有限值都逐位相同。例如输入半精度位模式 `0x001a`、置信度 `194/255`，原 pass 输出为 `0x0019`。这是非常小的数值差异，不能据此判断有可见画质差，但也不能称为完全等价。

因此这项没有进入本轮产品代码；guidance 着色器和全部调用仍保留。证据保存在工作区 `.tools/067-r2-resources/identity-guidance-probe.txt`。后续若要执行，应先明确数值误差容限并验证 NR 的时序输出。

## 3. 为什么当前 XeSS FG 可能体验更好

**目前不能把差异归因于两家的模型优劣。** 本项目的集成、默认配置和显示路径不同，可能分别影响流畅度、输入延迟、UI 响应和 HDR 观感。

| 对照项 | XeSS FG | DLSS FG | 可以得出的判断 |
| --- | --- | --- | --- |
| 插帧呈现 | SDK 代理交换链负责生成和安排呈现 | 直接 NGX 生成，再由 Magpie 的共享环/FIFO/时钟呈现 | XeSS 采用的呈现整合更完整；DLSS 自管节奏中的短间隔追赶可能影响顺滑感 |
| 低延迟 | 已创建 XeLL、开启低延迟、连接 XeSS FG，提供 Sleep 和阶段标记 | 未接入 Reflex | XeSS 有已接入的低延迟机制；不能据此宣称源游戏端到端延迟已验证更低 |
| 每张插帧的应用工作 | Magpie 不逐张接收 SDK 生成图像再复制发布 | 每张生成帧都经过应用端完成等待、共享发布、前端绘制 | DLSS 在高倍率时有更多应用端调度与数据搬运 |
| 帧身份/结果 | `SetPresentId` 与 XeLL 同 ID，并查询 `GetLastPresentStatus` | 捕获 ID 与 generated 布尔值，缺少贯通的 MFG 子索引/present ID | DLSS 对实际插帧呈现的可观测性较弱 |
| Magpie 自身 UI | 独立 DirectComposition UI 层 | 工具栏/光标在生成完成后的前端帧上绘制，共用呈现路径 | XeSS 的 UI 更新能更独立；两者都不能据此认为已经分离源游戏 HUD |
| 默认光流 | XeSS FG x2 默认为 None | DLSS FG 默认为 NVOF Balanced | 直接比较默认值不是相同输入/开销条件的 A/B；本轮不更改用户设置 |
| 引导尺寸 | 适配到最终效果尺寸后，再放到终端呈现区域 | 优先使用原捕获尺寸；源尺寸大于最终颜色时走 Zero 回退 | 特定降采样组合可能没有按相同引导合同比较 |
| HDR | HDR10/R10 终端与代理交换链，独立 UI 用 FP16 | FP16 管线，特定白点下有 FG 前后归一化桥接 | 高光/色彩差异应先核对颜色链，不能都归为插帧算法问题 |

本地证据：[XeLL 接入](../../../src/Magpie.Core/XeSSFGPresenter.cpp#L513)、[Sleep/标记](../../../src/Magpie.Core/XeSSFGPresenter.cpp#L715)、[呈现及结果](../../../src/Magpie.Core/XeSSFGPresenter.cpp#L808)、[UI 绘制分支](../../../src/Magpie.Core/Renderer.cpp#L924)、[XeSS HDR 格式](../../../src/Magpie.Core/XeSSFGPresenter.cpp#L18)。

官方 XeSS 1.3 指南明确：代理交换链负责插帧节奏，在非 Intel GPU 上使用高优先级后台线程和内部队列；XeLL 与 FG 连接并使用同一帧 ID。这与本地已接入的路径相符。[Intel 官方指南](https://github.com/intel/xess/blob/8fe81bdbbaf00b3c1b733fd0d830c333dc84e6f0/doc/xess_fg_developer_guide_english.md#programming-guide)

直接 NGX 的文档把呈现责任留给应用。因此 Magpie 自管 FIFO 本身是合法路线，缺口在实现完整性和质量验证，而不是“没有代理交换链所以一定错误”。[NVIDIA NGX FG 指南 §7](https://github.com/NVIDIA/DLSS/blob/a291cc7d2cc642a51566f3dfd5376f635cd1b284/doc/DLSS-FG%20Programming%20Guide.pdf)

限制：XeSS 的模型和代理内部调度也不是这里完整可审计的源码；XeLL 调用只覆盖 Magpie 自身处理阶段。其 `frameRenderTime` 当前来自前端实际调用间隔，不是源游戏的引擎帧时间。双方都需要用相同场景、倍率、光流条件和显示模式做对照。

对照建议先固定 2x。Intel 当前指南在非 Intel GPU 上只承诺生成一张中间帧，本地也按 SDK 能力检查；不能拿 XeSS 2x 与 DLSS 4x 的延迟直接判断算法优劣。[官方要求](https://github.com/intel/xess/blob/8fe81bdbbaf00b3c1b733fd0d830c333dc84e6f0/doc/xess_fg_developer_guide_english.md#requirements)

本轮在线资料固定为 Intel `8fe81bdb`（2026-07-24）；本地指南为 FG/XeLL 1.3，运行包 `libxess_fg.dll=1.3.1.78`、`libxell.dll=1.3.0.5`。不以“名称带 ZeroMV”推断现在没有可选运动估算。

## 4. DLSS FG 仍需处理的缺陷或风险

| 问题 | 证据强度 | 当前处理 |
| --- | --- | --- |
| 迟到一个周期以内可出现过短帧间隔，边界处不连续 | 已用现有时钟头文件验证：10 ms 周期、迟到 9/10 ms，下一 deadline 间隔 1/0 ms | 留在 R2-03；需测试相位修正对实际显示的影响 |
| 捕获节奏估计混入处理/投递开销，只扣除 ring wait | 源码确认；已有捕获 timestamp 未用于该估计 | 留在 R2-03，先验证各捕获后端的时间合同 |
| FIFO 仅限容量，缺少生成帧年龄预算和过时插帧淘汰 | 源码确认 | 留在 R2-04；不得通过跳过 NGX 必要的 Evaluate 索引实现 |
| 每张插帧串行等待 Evaluate 和发布复制，单输出/allocator 阻止直接异步复用 | 源码确认 | 本轮只消除事件/映射开销，R2-07/08 继续设计安全资源槽 |
| 旧捕获序列被拒绝后返回 false，上层统一 Retry，并可能以已推进的 key 复用旧底图 | 源码状态流风险，未做窗口故障复现 | R2-02 需明确 Retry/Drop 并做故障注入验证 |
| FG 停用函数未统一重设 `_hasFrameGeneration`、FIFO 等状态 | 源码确认存在分散状态；实际异常后影响待测试 | R2-02 做完整状态转换修复 |
| NR/互操作/发布路径仍有无超时 CPU 等待，Drain 失败后的安全退役尚待统一 | 源码确认 | R2-02 统一处理；本轮未移除这些保护或扩大异步在途工作 |
| 源尺寸大于 FG 输出时回退 Zero，但请求的应用光流仍可能被生产 | 源码确认；当前回退会记录日志 | 先决定适配后绑定还是明确停止不被消费的工作，不能盲目改变引导尺寸 |
| Reflex、异步呈现标记和可靠的显示端计量未集成 | 源码搜索与官方对照确认 | R2-09，不能用 DXGI MaximumFrameLatency=1 宣称已支持 Reflex |

此表不重复把“没有源游戏深度/原生运动”列成待补功能，遵守此前约定。关于重置、MFG 顺序和禁用标志，已确认基本实现存在；没有证据说明当前正常路径把生成帧索引整体排反。

## 5. 本轮验证与验收边界

自动检查：

- `tests/Run-DlssR2ResourceTests.ps1`：只创建 WARP 软件设备，提取当前生产函数及着色器，不加载 NGX、NVOF、XeSS DLL，不开窗口。
- 25 组 NR 残差参数/尺寸组合，对比直接输出与原中间纹理复制路径，RGBA8 结果逐字节相同；覆盖无 UAV 回退、输入输出同一纹理回退、输出对象改变。
- FG 持续映射覆盖 96 次 GPU 缓冲写入、三个标志槽，确认只读取首字节、事件被复用；过期事件唤醒不能授权未完成输出。
- 测试分别编译计时开关关闭和开启两个版本；两者资源结果均通过。
- 复用现有参数/迁移回归，八个 RTX 别名迁移、默认/异常参数以及自动 HDR 输入/能力案例通过。
- Release x64 默认选项验证构建通过。首轮构建遇到常量条件警告作为错误，已改为 `if constexpr` 后通过，没有降低警告等级。

验证构建可用 `/p:EnableNativeBackendTiming=true` 开启 NR/NVOF GPU 计时和 FG 详细汇总；通常构建默认 false，不新增用户配置项。只检查库内部调用时长不能替代显示端帧时间；本轮没有新增常开逐帧跟踪。

用户验收重点：NR 残差开关及滑条、100/75/50% 输入、NR+FG、停止/恢复、SDR/HDR，FG 2/3/4x（设备支持范围内）。这部分仍待用户测试；目前可报告的是删除了哪些多余操作和软件设备输出等价，不能报告实测 FPS/延迟收益。
