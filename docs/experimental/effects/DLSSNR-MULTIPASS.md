# DLSSNR Multi Pass（0.6.8 local）

在 DLSSNR 参数第二列“NR 界面修正”下方，选择 `Multi Pass` 的 `1 / 2 / 3`。默认是 1，最多是 3。2 次显示第三列，3 次显示第四列；列标题分别是 `DLSSNR · Pass 1 / 2 / 3`。窗口较窄时可以横向滚动。Multi Pass 仅显示名称，不显示串联说明提示。

新增层使用 DLSSNR 默认参数。减少次数只隐藏并停用后面的层，保留它们的设置，再次增加次数会恢复。恢复某个参数的默认值仅影响该层。Multi Pass 使用下拉框直接选择次数。

第二列尾部、`Multi Pass` 后增加“抗闪烁”下拉框，默认“无”。

| 选项 | 作用 |
| --- | --- |
| 无 | 保持当前 NR 输出，不分配额外抗闪烁历史 |
| 静态累积 | 在原输入颜色稳定的区域累积修正，运动或颜色变化处使用当前结果 |
| 光流累积 | 先用光流对齐历史，再验证原输入颜色并累积修正 |
| 光流累积+ | 光流验证后，分别平滑修正的持续性与出现时的幅度，缓和修正反复出现／消失 |
| 低频时域重建 | 半分辨率残差观察与原分辨率历史联合重建；保留当前高频差分，主要稳定低频修正 |

单层时稳定 `Pass 1 − 原输入`；多层时稳定 `最终层 − Pass 1`，然后加回 Pass 1，因此多层模式主要抑制后续层新增修正的闪烁。处理位于串联输出之后，不把累积结果送回下一帧 NGX。各层 NR 内部的分辨率调整保持原行为；低频时域重建在输出端额外提取低分辨率差分并做联合重建。

光流累积、光流累积+、低频时域重建复用现有光流选择；光流方法为“无”时自动请求 AMDOF Quality，供外部抗闪烁使用，NR 自身仍遵循原来的光流设置。运行中光流无效时清除旧历史并退回静态验证；初始化阶段仍遵循现有光流服务的可用性要求。相似颜色不保证对应同一物体，运动边缘、反射和 UI 仍需实测。

切换“无 / 静态累积 / 光流累积 / 光流累积+ / 低频时域重建”沿用自动重启流程。即时修改 NR 参数、上游输入修订、捕获重置、资源变化或超过 250 ms 的帧间隔都会使旧历史失效。同一个捕获帧不重复累积。静态累积、光流累积和低频时域重建的幅度时间常数暂定 80 ms，约相当于 60 次真实更新/秒时 0.812 的基础历史权重，再按输入匹配质量降低。

抗闪烁选项保存为 `antiFlicker=0/1/2/3/4`，分别对应无、静态累积、光流累积、光流累积+、低频时域重建。旧配置值保持原含义，缺省为 0；恢复默认值会关闭抗闪烁。各路线互斥选择。

光流累积+的持续性采用 60 ms 出现、180 ms 消退；出现时的条件幅度采用 80 ms 更新，缺失观察不把零值混入该幅度。输入变化或历史失效立即取消旧修正。弱于阈值的修正可能被削弱，反复出现的修正可能比普通均值保留得更强；它不保证时间均值不变。

低频时域重建固定从最终有符号差分提取宽高各约一半的观察，不随“输入分辨率”百分比改变。低分辨率差分用原图颜色引导升采样，在同一输出 dispatch 中与经过验证的原分辨率历史混合；高频补偿使用当前帧，以保住细线和孤立修正。未加入 jitter，也不从 NGX 内部直接取低分辨率纹理，因此没有减少模型推理或现有缩放成本；高频补偿中的闪烁仍可能存在。低频时域重建相比另外三个抗闪烁选项 额外增加两张半分辨率 RGBA16F 纹理和一次提取 dispatch。

算法公式、阈值、内存和验收范围见[技术路线文档第 14 节](../design/20260914-dlssnr-temporal-stabilization-routes.md#14-068-local-扩展实施f--g)。

| 每层独立参数 | 默认值 | 范围 |
| --- | --- | --- |
| NR Style | 0 | 0～2 |
| NR Intensity | 1 | 0～2 |
| Local Tone Strength | 1 | 0～2 |
| Local Structure Strength | 1 | 0～2 |
| Skin Structure Strength | 0 | 0～2 |
| Automatic Mask | 关闭 | 开 / 关 |
| NR UI Correction | 关闭 | 开 / 关 |

第一列 Detail Control 的输入分辨率、Residual 系列、Shadow / Structure、Reflection / Glow 和光流设置由各层共用。每一层处理上一层输出，保持效果器输入与输出分辨率相同。光流沿用共享捕获帧服务，不为中间画面重新估算。

运行中的参数面板也支持次数和各层设置。改变次数会沿用现有自动重启流程重建处理链；各层七个独立参数沿用即时应用规则。SDR 的共享细节参数沿用现有应用规则；HDR 下原有分辨率调整和 Residual 限制继续适用。

多次处理会增加资源使用量，具体画面、耗时和显存开销需要实机对比。

## 配置与资源

效果列表仍保存一个 `DLSSNR\DLSSNR_AI_Filter` 条目。次数使用 `multiPass`，Pass 1 沿用旧参数名，后两层使用 `pass2_` / `pass3_` 前缀，例如 `pass2_intensity`。缺省次数为 1；缺失后两层参数时，后端和界面均从默认值读取，不复制 Pass 1。所有参数进入现有参数字典保存与导入导出，不增加配置版本或迁移旧配置。

每层拥有独立 NGX 特征、参数、命令队列、共享资源、围栏和时序历史。中间纹理由完整处理链持有；重建时先排空队列，再释放全部实例并创建新链。SDK 初始化、关闭和兼容钩子由共享会话持有，最后一个特征释放后才关闭。

即时改变前一层参数时，会提高后续层的输入修订号，使相同捕获帧也重新处理。多层初始化、尺寸重建或任意层评估失败时拒绝完整处理链；默认单层保留原有不可用回退行为。
